# 13 October 2026

Four entries today:

- `Response::send()` leaves an earlier status line alone
- Recording sends is an application setting; a missing SMTP host says so
- `Pagination` reads a page number from a URL whatever it is
- Closing a connection another instance closed is a no-op

<!-- more -->

## `Response::send()` leaves an earlier status line alone

### Fixed

- `Response::send()` called `http_response_code()` unconditionally. On PHP 8.5 that call, after a
  `header('HTTP/1.1 404 Not Found')` a legacy controller had written, has no effect and logs
  *"Calling http_response_code() after header('HTTP/...') has no effect"* — once per such
  response. It now sets the status only when it differs from the one in effect.

### Documentation

- Framework Guide, `Response` API reference: what `send()` does with a status already set, and
  how a front controller passes a controller's own status into `make()`.

## Recording sends is an application setting; a missing SMTP host says so

### Added

- `'mail' => ['record' => false]` in `app/app.php` turns off the `mails` row that every
  `Email::send()` writes. An application that keeps its own row per message got two — one
  measured sixteen pairs in its first hundred rows — and the static `Email::sendMail()`, which
  builds its own `Email`, had no way to turn it off. `$email->recordToMails = false` still does
  it for one message.

### Fixed

- With no `smtp_host`, a send failed with Symfony's *"The mailer DSN is invalid."* — the DSN
  built from an empty host is `smtp://user:pass@:0`, so the message pointed at the credentials.
  It now fails with *"SMTP not configured: smtp_host is empty."*

### Documentation

- Email Guide: the `record` setting beside the audit log, and the missing-host error under SMTP
  settings. Upgrade Guide: two rows.

## `Pagination` reads a page number from a URL whatever it is

### Fixed

- `new Html\Pagination($pages, $page, $url)` took `int` for both numbers, so a non-numeric page
  taken from the URL — `/page/abc` from a crawler — was a `TypeError` and a broken page. Both
  accept `int|string|null` and are read with `(int)`: `'3'` is page 3, anything else page 1.

### Documentation

- HTML Components Guide, *Pagination*: how the numbers are read.

## Closing a connection another instance closed is a no-op

### Fixed

- `Database::close()` called `mysqli_close()` / `pg_close()` on whatever link it held. Two
  instances given the same link without `clone` — a legacy and a modern handle over one
  connection — both own it, so the second destructor threw *"mysqli object is already closed"*:
  a fatal in the log at shutdown, after the response had gone, twenty times a minute on one
  production site. A link that is already closed now makes `close()` return `false`.

### Documentation

- Database API Guide, *Cloning a `Database`*: a link shared some other way.
