## `Response::send()` leaves an earlier status line alone

### Fixed

- `Response::send()` called `http_response_code()` unconditionally. On PHP 8.5 that call, after a
  `header('HTTP/1.1 404 Not Found')` a legacy controller had written, has no effect and logs
  *"Calling http_response_code() after header('HTTP/...') has no effect"* — once per such
  response. It now sets the status only when it differs from the one in effect.

### Documentation

- Framework Guide, `Response` API reference: what `send()` does with a status already set, and
  how a front controller passes a controller's own status into `make()`.

## Recording sends is an application setting; a missing SMTP host says so

### Added

- `'mail' => ['record' => false]` in `app/app.php` turns off the `mails` row that every
  `Email::send()` writes. An application that keeps its own row per message got two — one
  measured sixteen pairs in its first hundred rows — and the static `Email::sendMail()`, which
  builds its own `Email`, had no way to turn it off. `$email->recordToMails = false` still does
  it for one message.

### Fixed

- With no `smtp_host`, a send failed with Symfony's *"The mailer DSN is invalid."* — the DSN
  built from an empty host is `smtp://user:pass@:0`, so the message pointed at the credentials.
  It now fails with *"SMTP not configured: smtp_host is empty."*

### Documentation

- Email Guide: the `record` setting beside the audit log, and the missing-host error under SMTP
  settings. Upgrade Guide: two rows.

## `Pagination` reads a page number from a URL whatever it is

### Fixed

- `new Html\Pagination($pages, $page, $url)` took `int` for both numbers, so a non-numeric page
  taken from the URL — `/page/abc` from a crawler — was a `TypeError` and a broken page. Both
  accept `int|string|null` and are read with `(int)`: `'3'` is page 3, anything else page 1.

### Documentation

- HTML Components Guide, *Pagination*: how the numbers are read.

## Closing a connection another instance closed is a no-op

### Fixed

- `Database::close()` called `mysqli_close()` / `pg_close()` on whatever link it held. Two
  instances given the same link without `clone` — a legacy and a modern handle over one
  connection — both own it, so the second destructor threw *"mysqli object is already closed"*:
  a fatal in the log at shutdown, after the response had gone, twenty times a minute on one
  production site. A link that is already closed now makes `close()` return `false`.

### Documentation

- Database API Guide, *Cloning a `Database`*: a link shared some other way.

## A table's footer search reads nothing undeclared and stays within its table

### Fixed

- `Html\Datatable` with `footerTextSearch` emitted a blur handler that restored
  `asInitVals[…]`, which nothing declared: every empty footer box that lost focus threw
  *"ReferenceError: asInitVals is not defined"*. The focus/blur pair imitated a placeholder by
  writing the label into the value; the boxes carry a `placeholder` attribute, so it is gone.
- The footer `keyup` was bound with `$("tfoot input")`, every footer box on the page, so with
  two tables typing under one filtered both. It is bound to its own table's footer.

### Documentation

- HTML Components Guide, *Filtering one column*: the boxes filter their own table only.

## A date field is ten characters wide, and its `form-control` is the project's to drop

### Added

- `component_classes.date` (default `form-control`): the class `Html\Date` puts on its field.
  `''` leaves it off. Bootstrap's `.form-control` is `display:block; width:100%`, so outside a
  grid column the field spanned the page — fifty-one administration views in one application —
  and the class was hard-coded.

### Fixed

- The field carries `size="10"`, so with no class it is ten characters wide rather than the
  browser's default. Its classes are escaped.

### Documentation

- HTML Components Guide, *Date and time*: the width and the class.

## A model in JSON is its data

### Fixed

- `Model` implements `JsonSerializable`, returning `getData()`. `json_encode()` walked a model's
  public properties, and `$controller` leads to the application and back to the model:
  *"Recursion detected"*, `false`, and a 500 from every API response holding a model one level
  down. On one production site that was a user's record (its package, a model in a field) and
  their tickets (departments and the user, arrays of models).

### Documentation

- API Guide, *`getData()` and the columns it returns*: what a model becomes in JSON. Upgrade
  Guide: one row.

## Reading — and taking — a column's search value before the Datasource runs

### Added

- `Datasource::columnSearch(int $column)` returns a column's search value from DataTables
  1.10 (`columns[N][search][value]`) or 1.9 (`sSearch_N`) alike. `render()` translated the first
  into the second only when it ran, so an application building its own condition beforehand —
  one has about 470 reads of `sSearch_N` — found nothing on a 1.10 request.
- `Datasource::takeColumnSearch(int $column)` reads it and keeps `render()` from applying it as
  a `LIKE` on the column as well, for a filter the application turns into its own condition.

### Documentation

- HTML Components Guide, *Filtering one column*: both methods.

## A multiple-choice column filter reads as its values

### Fixed

- A `<select multiple>` column filter posts an array — `fnFilter(jQuery(this).val(), N)`,
  sent as `columns[N][search][value][]=…`. `Datasource::columnSearch()` read it as `''`, dropping
  the filter, and the 1.10 translation cast it to the word `Array`, which `render()` applied as
  `LIKE '%Array%'`. Both now read it as its non-empty values joined with commas — `'3,7'` — the
  form a 1.9 client sent the same choice in.

### Documentation

- HTML Components Guide, *Filtering one column*: a multiple choice.

## A user that did not load is saved as a new one

### Fixed

- `new User($id)` for an id with no row kept `_isnew = 0` and the default `userid` of 1, so its
  `save()` ran `UPDATE users … WHERE userid = 1` — the Guest row, or nothing — and then wrote its
  details against that id. An application creating accounts from `new User($_SESSION['uid'])`
  lost every sign-up after upgrading, with nothing logged. A user that did not load is now new,
  and saving it inserts a row with its own id.
- A save whose `UPDATE` finds no row — the user was deleted after loading — writes nothing,
  details included, and records why in `_errors`. Zero affected rows alone is not taken as
  missing: MySQL reports that for an unchanged row too, so the row is looked for first.

### Documentation

- Authentication Guide, *Loading Users*: what a user that did not load is. Upgrade Guide: one row.

## Language models: a client, a tool loop, a call log and one admin screen

### Added

- `Pramnos\Llm`, behind a new `llm` feature: `Client::ask()` and `askWithTools()` over the
  OpenAI-compatible providers (OpenAI, DeepSeek, Gemini, Mistral built in; an application adds
  and overrides them in `app.php`), with `Tools::fromMcp()` turning MCP tools into the loop's
  tools. The loop forbids tools on the last round and tells the model not to claim what no tool
  did; a *due* tool is forced before the end, and a verifier can send a wrong answer back once.
  Answers are plain arrays.
- Policies an application plugs in, each defaulting to "allow": `Policy\Limits` (plans, quotas;
  told what each round spent), `Policy\Consent`, `Policy\Router` (the request's organisation,
  its own provider or key) and `Policy\DataRule` — data a tool tags (`Tools::tag()`) that may only
  go to some providers moves the answer to one that may take it, or is withheld.
- `llm_calls`: every call, failures included, with its cost frozen at write time from editable
  unit prices (`llm_prices`, seeded) and `null` for a model nobody priced. `llm:prune` keeps 90
  days and is scheduled daily. `Billing\OpenAiCosts` reads what OpenAI billed.
- `/admin/Ai` (`admin.ai`): providers, keys (encrypted, never printed back), models, features,
  prices, OpenAI billing and the call log — the one screen for these settings, which an
  application extends with its own sections (`'admin_sections'`, `Llm\Admin\Section`) rather than
  a second screen. `init --features=…,llm` writes the admin wrapper.
- The settings and the table keep the names an application that already ran this code uses
  (`llm_*`, `llm_calls`); a table that exists is kept, and gains `tokens`, filled from each
  row's usage.

### Documentation

- New: the Language models guide. Console Guide: `llm:`.

## `/admin/Ai` shows the application's own sections

### Fixed

- The sections an application declares in `'llm' => ['admin_sections' => [...]]` were saved but
  never drawn. The controller handed them to the view as `sections`, which is also `View`'s own
  protected property: the assignment went through `__set`, and the template, running in the
  view's scope, read the real — empty — property. The variable is `appSections`.
  Any view variable named after a property of `View` has the same problem (`sections`, `path`,
  `model`, `_layout`, …); the test that caught this renders the template through a real `View`.

## An empty order is no order

### Fixed

- `Model::_getList($filter, '')` ordered by primary key descending, as `null` does. An empty
  string is the caller saying "no order" — the framework's first `_getList()` read it that way,
  and wrappers declared `getList($filter = '', $order = '')` relied on it — so every such list
  came back upside down: one application's invoices, newest at the bottom for years, newest at
  the top after upgrading. `''` now adds no `ORDER BY`; `null` is still newest first.

### Documentation

- ORM Guide: what the order argument's two empty values mean. Upgrade Guide: one row.

## Conversations with a model: memory, background questions, schedules and consent

### Added

- `Pramnos\Llm\Chat`: conversations kept per person (`Conversations`, `Scope`), what a model
  remembers about them (`Memory`), questions answered by the queue worker (`Asks`, a `chat_ask`
  task the worker knows without being told) and questions asked again on a schedule (`Routines`,
  run every minute by `llm:routines`, telling the owner with `RoutineReady`). What a conversation
  is about — prompt, tools, checks, what an answer produced — is an application's
  `Chat\Assistant`; `BaseAssistant` answers every hook with a default.
- `Policy\StoredConsent`: agreement to a provider kept in `ai_consents`, checked only for a
  provider marked `requires_consent`.
- `Pramnos\Llm\DocumentText` (Word, OpenDocument, text, Markdown and email to words, and their
  pictures) and `Pramnos\Email\MailMessage` (an email read into its parts).
- Tables `chat_conversations`, `chat_messages`, `chat_memory`, `chat_asks`, `ai_consents` and
  `ai_routines`, under the `llm` feature; an application that already has them keeps them, and
  `chat_conversations` and `chat_messages` gain `tags` and `extra`.
- `Queue\Worker::FRAMEWORK_HANDLERS`: the framework's own task types, answered without being
  registered; an application registering the same type wins.

### Documentation

- Language models guide: *Conversations*. Email Guide: *Reading an email*.

## A conversation's assistant: its bag, its clock, and a limit only on adding

### Fixed

- What `Assistant::question()` put in the turn's `bag` was lost before `tools()` and `answered()`
  ran: the turn was built again after it. The bag is carried over.
- `Routines` asked `routineRefusal()` the same question to offer the tools, before every run and
  when one was added, so a limit on how many may be active either stopped every run once reached
  or was not enforced. It is now `routineRefusal(Scope $scope, bool $adding = false)`, `true`
  when one is created or resumed — resuming a paused routine adds an active one too.

### Added

- `Assistant::timezone(Scope)`: the clock a schedule said in words is meant on, for the
  `schedule_task` tool. `BaseAssistant` answers the server's zone.

### What breaks in subclasses

- An assistant implementing `Chat\Assistant` directly — not through `BaseAssistant` — needs
  `timezone(Scope $scope): string`, and its `routineRefusal()` must take `bool $adding = false`.

## A resync keeps the components a project changed; conversation screens under `llm/`

### Fixed

- `project:resync --spa-components` replaced every shared component that differed from the
  framework's — a DataTable keyed for duplicate rows, a Field with its own debounce — and printed
  `updated`. What `init`, `create:crud` and the resync write is now recorded by hash in
  `app/shipped-files.json`; a file changed since, or never recorded, is reported
  `kept (locally changed)` or `kept (not written by the framework)` and left alone.
  `--overwrite` takes the framework's copy anyway.
- The conversation screens shipped at `components/Chat.svelte`, `lib/markdown.js`,
  `__tests__/Chat.test.js` — paths an application's own chat screen and tests already used. They
  are now under `components/llm/`, `lib/llm/` and `__tests__/llm/`.
- The conversation API and page checked the assistant's connection before the router ran, so an
  organisation on its own provider or key was told nothing was set up, or asked to agree to the
  installation's provider. They check the routed one: `Conversations::connection()`.

### Added

- Agreement per feature: `GET`/`POST`/`DELETE /chat/consent?feature=…` (`chat` by default), each
  on the provider the router sends that feature to; `AiConsent`'s `kind`. A feature the
  application does not have is a 422.
- `AiConsent`'s `notice(consent)` snippet — and `Chat`'s `consentNotice` — for the agreement's

## A reserved word is quoted wherever a column is named

### Fixed

- `select(['usage'])` on `llm_calls` failed on MySQL: `usage` is reserved there and was not in the
  builder's list of reserved words. It is now, with the other MySQL-only reserved words found as
  column names (`rank`, `row`, `lock`, `read`, `schema`, `system`, …). A reserved word is also
  quoted when qualified (`c.usage`) and as an alias (`tokens AS order`); a mixed-case alias and a
  raw expression are left as written.

### Documentation

- Query Builder Guide: *Reserved words*.

## A push is recorded at the moment it was sent, in every zone

### Fixed

- `Push\Log` wrote `sent` as PHP's local time without an offset into a `timestamptz`, which the
  database read in its own zone — on a PHP in Europe/Athens and a database on UTC, every push was
  recorded hours in the future, and the windows of `stats()` and `prune()` shifted with it. All
  three now use UTC with the offset.

### Documentation

- Push Guide: what `sent` holds. Upgrade Guide: one row, for rows written before.

## A migration that made its table is not declined for want of its hypertable

### Fixed

- On a backend without TimescaleDB, the `auth` migrations that create a table and then convert
  it — `twofactor_attempts`, `user_activity_log`, `user_consents`, `data_processing_records`,
  `gdpr_requests`, `tokenactions` — were declined, "nothing was applied", after creating the
  table; the next `migrate`, finding it, recorded them as applied. They now treat the conversion
  as the extra it is, and are applied the first time.
- `ifCapable()` on an engine (`ENGINE_POSTGRESQL`, `ENGINE_MYSQL`, `ENGINE_MARIADB`) no longer
  declines the migration when the engine is another: PostgreSQL-only indexes skipped on MariaDB
  are not work left undone.

### Added

- `SchemaBuilder::whenCapable()`: run when capable, otherwise nothing, and the migration is not
  held back — for an extra that something else repairs when the capability arrives.

### Documentation

- Schema Builder Guide: `ifCapable()` or `whenCapable()`. Hypertable Guide: the migration
  pattern uses `whenCapable()`.

## Every framework migration runs on an installation with a table prefix

### Fixed

- Nineteen framework migrations named tables in raw SQL — `public.applications`,
  `` `usertokens` ``, `applications.oauth2_application_grants`, `ALTER TABLE users` — and so
  failed, or skipped their work, on the first installation with a table prefix; the `applications`
  group, `oauth2_application_grants` and its views, `user_organizations`,
  `user_app_authorizations`, the consent trigger, the RBAC functions and the slow-call views
  among them. Every table in a migration's raw SQL is now named through `$schema->quoteTable()`;
  `oauth2_application_grants` is built with the schema builder outright.
- `SchemaBuilder` resolved the table being built and not the one a foreign key referenced, so
  `->on('applications')` named an unprefixed table, and `->on('authserver.x')` a database on
  MySQL. It resolves both.
- `add_missing_foreign_keys_to_existing_tables` and `add_missing_indexes_to_existing_tables` used
  `schema('public')`, which on MySQL becomes `{prefix}public_*`, and looked constraints and
  indexes up by bare name. A foreign key between columns of different types — `INT` against an
  `increments()`'s `INT UNSIGNED` — is skipped with the reason instead of failing the batch; new
  MySQL installations get the referencing columns unsigned, so the keys are created.
- `CorsMiddleware::fromApplicationSettings()` was raw SQL over the same names; it is a query-builder
  query. On PostgreSQL it could read neither column: `cors_origins` is a `TEXT[]`, which never
  parsed, so every application allowed `*`, and `cors_enabled` came back `'f'`, which PHP reads
  as true.

### Added

- `PrefixedFrameworkMigrationsTest`: every framework migration on a fresh MySQL and PostgreSQL
  installation with a prefix — nothing fails, nothing is declined but for a missing capability.
- `TablePrefixInQueriesTest` refuses a framework table named in a migration's raw SQL, which
  reaches the statements a fresh run does not: `down()` and the other dialect's branch.

### Documentation

- Migration Guide: *Raw SQL Migrations* — what the builder names, and naming tables in what it
  does not. Schema Builder Guide: the referenced table, and matching an `increments()` on MySQL.
  Upgrade Guide: two rows — CORS on PostgreSQL, and migrations on a prefixed installation.

## MariaDB: dropping a CHECK, and a column's CHECK after its COMMENT

### Fixed

- `allow_jwt_bearer_in_oauth2_application_grants` and `open_webhook_event_types` dropped their
  CHECK with `DROP CHECK`, which MariaDB refuses; and MariaDB keeps a CHECK written on a column as
  part of the column, named after it, which `DROP CONSTRAINT` does not reach either. Both go
  through the new `SchemaBuilder::dropCheck()`.
- `create_oauth2_application_grants_table` writes its CHECK named and table-level,
  `chk_oauth2_grant_type`, so the next migration can drop it on every database.
- The schema grammar wrote a column's `CHECK` before its `COMMENT`, which MariaDB refuses; the
  COMMENT now comes first.

### Added

- `SchemaBuilder::dropCheck($table, $name)`.
- A `mariadb` service (MariaDB 10.11), profile-gated, and `./dockertest --mariadb`, which starts it
  and runs the `mariadb` group: the grants migrations and every framework migration on a prefixed
  installation. Excluded from the main suite.

### Documentation

- Testing Guide: *MariaDB, when a change is dialect-sensitive*. Schema Builder Guide: *Dropping a
  CHECK constraint*.

## A queue worker's task sees the settings as they are now

### Fixed

- `queue:process --daemon` read the settings once and kept them for its whole life, so a
  provider or API key an administrator saved was never seen by the tasks that followed —
  "API key saved", then "no API key". Before each task it claims, the worker calls
  `Settings::refresh()` and `Llm\Connection::forget()`. An idle worker reads nothing.

## The analyst writes its own SQL, and files to download

### Added

- Three analyst tools, off until the application turns them on — `'llm' => ['analyst' => ['sql'
  => true, 'export' => true]]`:
    - `schema`: tables, columns, keys, and the application's notes about them (`'schema' => […]`);
    - `sql`: one SELECT, up to 200 rows to the model;
    - `export_csv`: up to 100,000 rows to a CSV file with a byte-order mark. The model gets the
      link, the count and five rows.
- `Analyst\ReadOnlySql` guards every statement:
    - the read-only lexer;
    - no function that waits, locks or reads files;
    - a read-only transaction, rolled back;
    - a time limit on each engine (`sql_seconds`, 30 by default);
    - a `LIMIT` when the statement has none.
- `Analyst\Exports` keeps the files for seven days, under names short enough to survive
  redaction. `/admin/Ai/export/<name>` serves a file only to the administrator it was made for.
- `Database\ReadOnlyConnection`: the `database_readonly_dsn` account, shared by `db-inspect`
  and the analyst.
- `Analyst::tools()` and `mcpTools()` take the administrator's id.
  `AiController::adminId()`.

### Documentation

- LLM Guide, *Its own SQL, and files to download*.
