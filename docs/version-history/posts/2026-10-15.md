## An administration area theme, in the Theme Guide

### Documentation

- The Theme Guide's **An administration area theme** covers:
    - what `'admin' => ['theme' => …]` changes;
    - that the admin screens and their partials are not the theme's;
    - a checklist of what the theme must provide (the layout, `[MODULE]`, the UI system's CSS,
      the palette tokens, `renderCss()`/`renderJs()`, `pf-utils.js`, the admin menu and the
      flashed messages) and what goes wrong without each;
    - the optional parts (search box, side panel, badges);
    - a minimal four-file theme that reuses the site's head and footer.

## Writing views that survive a UI switch

### Documentation

- The Theme Guide's **Writing views that survive a UI switch** covers:
    - what `project:switch-ui` changes and leaves alone, including that it overwrites the
      default theme's layout files and `style.css` and never touches the application's views;
    - which components adapt on their own and which do not: `Datatable` with its default
      `$bootstrap = true` draws a Bootstrap 3 column picker, `Date` uses `form-control`, and
      `component_classes` is one map for every system;
    - what stays tied to a system;
    - a recommended approach, a before/after example, and a decision rule for a project with
      many templates.

## Moving a separate admin application into the area

### Documentation

- The Routing Guide's **Moving a separate admin application into the area** covers:
    - the two arrangements compared;
    - six steps (merging the config, controllers, views and their links, the application
      class's overrides, the front controller and `.htaccess`, and what carried the
      application's name);
    - running both under two prefixes during a transition, and why one prefix cannot serve both;
    - a table of requests to check after the move.

## "Saved." is shown

### Fixed

- The bundled admin screens flash "Saved." and redirect, and the screen they land on does not
  print the flash; neither did any scaffolded header. The message was written, carried across
  the redirect, and never seen. `Html\Flash::render()` draws the flash, escaped and taken so
  it is shown once. Every scaffolded `theme.html.php` calls it above `[MODULE]`, and every
  scaffolded stylesheet styles `pf-flash`.
- A view that shows the flash itself takes it first, so the layout repeats nothing.
  `ApplicationsController`, which read it without taking it, now takes it.

A project scaffolded before adds the one line to its layout. See the Upgrade Guide.
