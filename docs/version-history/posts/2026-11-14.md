## `Oauth::showErrorPage()` is styled inline, so it looks right inside any host theme (FW-502)

A refused `/oauth/authorize` request (an unregistered `redirect_uri`, say) rendered a bare
`<h1><p>` with no style of its own. Inside a host's theme that expects every block to carry its
own classes — Bootstrap, Tailwind, daisyUI, or none of them — it came out as an unstyled,
flush-left strip rather than a page.

### Fixed

- `Pramnos\Auth\Controllers\Oauth::showErrorPage()` now wraps the message in a self-contained,
  inline-styled card (centred, system-ui font, border and padding on the element itself), so it
  reads correctly regardless of what theme classes the host application does or does not define.

### Documentation

- `Pramnos_AuthServer_Integration_Guide.md`: a line on the error page's styling, under "What the
  refusal looks like".
