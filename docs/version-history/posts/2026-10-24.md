## Schema builder: choosing the ALTER algorithm (MySQL/MariaDB)

### Added

- `Blueprint::algorithm('INSTANT'|'INPLACE'|'COPY')` appends `, ALGORITHM=...` to every
  `ALTER TABLE` statement `SchemaGrammar::compileAlter()` emits for MySQL and MariaDB. If the
  server cannot honour the requested algorithm — e.g. `INSTANT` on a change that needs a table
  rebuild — the statement fails with the server's own error instead of silently falling back to
  a slower one. A no-op on PostgreSQL/TimescaleDB, where column changes are already
  metadata-only (FW-277).
- Lets a backfill of a column default on a table too large to rebuild unnoticed go through the
  query builder instead of raw SQL, closing the gap that had nannuka's visits/dailystats default
  migrations written by hand.

### Documentation

- Schema Builder guide: *Choosing the ALTER algorithm (MySQL/MariaDB)*, under *ALTER TABLE*.

## Conversations: link previews pruned, and history keeps its cards

### Added

- `conversations:unfurls-prune` (`Unfurls::prune()`) drops a link preview row not read again
  past `conversations.unfurl.keep_days` (30 by default — a cache, so it prunes even
  unconfigured), and the picture files no remaining row still names. Scheduled daily at 04:22.
  Before this, `pramnos.link_previews` and the `previews/` files beside the conversations'
  tree grew without limit.

### Changed

- `Messages::post()` now keeps a message's links (`Unfurls::remember()`) even when posted
  `quiet` — history imported from elsewhere used to get no card at all; it still gets no live
  update, mention or event, only the card it was missing.

### Documentation

- Conversations guide: *Link previews* — quiet history keeps its links; the prune command
  and its default retention.

## Moving from MySQL: the migration ledger is never copied in

### Fixed

- `db:migrate-from-mysql` left `schemaversion` out of every plan by default — a long-lived
  MySQL-origin install's own ledger has rows, and copying them flatly into a fresh target made
  `migrate` believe every framework migration had already run there, so it did nothing:
  `authserver`/`pramnos` schemas and hypertables were never built, everything stayed flat in
  `public`. `--tables=schemaversion` names it explicitly to move it anyway. The dry run now
  says so (`Migrator::plan()`'s new `ledger` key).

### Documentation

- Moving from MySQL guide: *schemaversion never moves*, under the table-creation rules — why,
  and why `migrate` must run to completion before this command's first copy.

## `Database::execute()` takes a literal argument now

### Fixed!

- `execute($sql, ...$arguments)`: the variadic was declared `&...$arguments` (by reference),
  which PHP has refused since 8.1 whenever a caller passes a literal instead of a pre-assigned
  variable — "Argument #n could not be passed by reference". `execute()` never wrote back into
  an argument for the caller to see, so the `&` bought nothing but that fatal. It also broke
  `mysqli_stmt::bind_param()`'s own by-reference requirement once the variadic stopped
  supplying references implicitly — the MySQL branch now takes explicit references to its own
  local copy of the arguments before `call_user_func_array()`.

#### What breaks in subclasses

A `Database` subclass or test double that overrides `execute()` keeping the old
`&...$arguments` fails to load ("Declaration ... must be compatible") — drop the `&` there too.
Nothing else: every ordinary call, with a literal or a variable, keeps working and now accepts
either.

- Upgrade Guide, *Since v1.2 — unreleased*: the signature change and the subclass action.
