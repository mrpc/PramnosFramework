## Claude as a built-in LLM provider, through Anthropic's Messages API

### Added

- **`anthropic` provider** — Claude Opus 5.5 (the default), Sonnet 5.5 and Haiku 5.5, with a
  million-token context window. It needs `llm_anthropic_api_key`, a key from the Claude Console,
  and is chosen like any other provider (`llm_provider`, a feature's model, a tier, a fallback).
- **`Transport\Anthropic`** — translates the client's OpenAI-shaped requests and answers to and
  from `POST /v1/messages`, so the tool loop, budgets, fallback, streaming and costing work
  unchanged. The system prompt goes apart and a later system note as text in the user's turn.
  Tools go as input schemas and their results as `tool_result` blocks. A forced tool call goes as
  `auto`, because the current models refuse forced tool use. The reasoning setting becomes
  `output_config.effort`. Every request asks for the prompt cache, and a cache read is costed as a
  cache hit. A streamed answer is read from the Messages API's own events.
- **`default_max_tokens`** in a provider's entry: the answer budget when nothing else sets one.
  Claude's is 16 000 because thinking spends from it; every other provider keeps 2 000.
- **Prices** for the three Claude models in `Pricing::SEED`. An installation whose `llm_prices` is
  already saved adds them on `/admin/Ai/settings`.

### Documentation

- LLM guide: a section on Claude: what is translated, and why thinking is not sent back.

## DeepSeek's retired `deepseek-chat` is asked for as `deepseek-flash`

DeepSeek set 24 July 2026 as the end of the names `deepseek-chat` and `deepseek-reasoner`, and
names its fast model `deepseek-flash` (DeepSeek-V4.1-Flash). The old name still answers, with no
notice of when it will stop.

### Changed

- **`Providers::RENAMED`** — a retired model name and its successor. `Connection::model()` returns
  the successor wherever the old name was saved, so an installation that saved `deepseek-chat`
  keeps working when DeepSeek stops accepting it. `deepseek-reasoner` is not renamed, because with
  reasoning off its thinking would be lost.
- **DeepSeek's default and curated models** are `deepseek-flash` and `deepseek-v4-pro`, both
  priced in `Pricing::SEED` with DeepSeek's off-peak half price. `Pricing::forModel()` costs a
  renamed model at the price saved under its old name when it has none of its own.

### Documentation

- LLM guide: retired model names. Upgrade Guide: a row for the new name.

## Answers read aloud by a speech server the application runs (Piper)

A browser's own voices can lack a language — no platform offers a free Greek one — so an assistant
read aloud needs a server. The application runs it; the framework knows how to ask it.

### Added

- **`Speech\Speech`** — speech providers in the language models' pattern: `BUILT_IN` entries, and
  the application's server, voice and options under `'llm' => ['speech' => …]` in app.php.
  `piper` speaks to Piper's HTTP server and receives WAV. `Speech::speak($text)` answers the audio,
  or 501 / 422 / 502 with why.
- **`POST {chat}/speak`** on the conversation API — `audio` in base64, `type`, `bytes`. It follows
  the `chat` path, so every mount of the API (`/chat`, `/assistant`) reads aloud at its own address.
- **One line per call in the `speech` log** — characters, milliseconds, bytes, the server's
  status — to size the server from.

### Documentation

- Screens guide: the endpoint and a section on reading answers aloud.

## Read aloud a sentence at a time, and the audio itself rather than base64

A whole answer synthesised before a word is heard is a wait, and a WAV in base64 is heavy: half a
minute of speech is close to two megabytes.

### Added

- **`pf-voice.js` with a speech server** — `createVoiceState({ server: fn })` reads an answer a
  sentence at a time (`PfVoice.splitSentences()`), fetching the next while one plays. Stop and
  barge-in silence it; a first sentence that fails falls back to the browser's voice.
  `hasServer` says which is in use.
- **`POST {chat}/speak` with `raw: true`** — the audio itself, under the speech server's own
  `Content-Type`, a third smaller than base64.

### Documentation

- Analyst guide, "Voice": the server mode. Screens guide: `raw`, the browser side, and why
  encoding (MP3) is the speech server's job rather than the framework's.

## Browser Errors: Delete deletes again

### Fixed

- **`LogController::deletejserror()`** read its hash as `$hash ?? option`, but `exec()` passes
  every action its arguments array, never null — so the hash was the string `Array`, nothing
  was deleted, and the page redirected as if it had been. The hash is now the request's option
  unless a string is given directly.

## Read aloud, «ό,τι» is the word, not «όμικρον τι»

### Fixed

- **`pf-speech-sanitizer.js`** — a voice read the comma in `ό,τι` as a letter's name. The comma
  goes before the text is spoken (`ό,τι`, `Ό, τι`); it sounds as `ότι` does. A comma after any
  other word stays.

## Read aloud, no «τελεία» or «κόμμα» where two marks met

### Fixed

- **`PfVoice.stripMarkdownForSpeech()`** turned every line's end into `. ` and a table's pipes
  into commas, so what was read aloud had `;.`, `:.`, `..`, `.,` and `,.` in it — and a voice
  (Piper's espeak among them) reads a mark that ends no phrase by its name. A line's end is a
  full stop only where it has no mark of its own, a table's outer pipes and separator row go,
  and wherever marks still meet only the first is kept.

## Google Cloud Text-to-Speech as a speech provider

### Added

- **`google` speech provider** (`Speech\GoogleCloud`) — Google Cloud Text-to-Speech, signed in
  with a `token` callable (a service account's access token) or an API key, given in app.php or
  kept encrypted in `llm_speech_google_api_key`. Without either it is not set up. The voice's
  language comes from its name, the options go into `audioConfig` (MP3 by default), and Google's
  own error comes back as the 502's message.
- **`Speech::speak()`**: a speech server's refusal that says why, rather than sending audio, now
  carries that reason in its 502.

## The Ask pages read answers aloud with the speech server

The conversations page and the analyst's read their answers with the browser's own voices even
where the application had a speech server, since only the API knew how to reach it.

### Added

- **`speak` on the pages** — `Chat\Web\ReadsAloud`, used by `ChatPageController` and
  `AiController`: a POST with the session's token, answered with the audio itself.
- **The chat templates** (every theme) draw `data-pf-chat-speak-server` and `data-pf-chat-csrf`
  where voice is on and a speech server is set up, and **`pf-chat.js`** gives the voice that
  server — read a sentence at a time, the browser's voice where a sentence fails.

## `project:resync --js` adds the voice's scripts where the voice is on

### Fixed

- An application that turned on `'llm' => ['voice' => true]` and resynced was not given
  `pf-voice.js` and `pf-speech-sanitizer.js` without `--all`, so its chat pages drew the voice's
  buttons with no script behind them. The voice now counts as a feature for the scripts
  (`FrameworkScripts::featuresOf()`, `llm.voice`): a resync adds them, and the health check names
  them missing only where the voice is on.

## Read aloud when the speech server fails: a fallback server, then the browser's voice from where it stopped

### Added

- **`'speech' => ['fallback' => '…']`** — a second provider, asked once when the one in use
  fails or is not set up (Piper beside Google). Both calls are logged; when both fail, the first
  provider's answer is returned.

### Changed

- **`pf-voice.js`** — a sentence that fails in the middle of an answer no longer ends the reading:
  the browser's voice reads on from that sentence. Before, only a failing first sentence fell back.

## The application's own words, said its way when read aloud

### Added

- **`'speech' => ['pronounce' => ['Ava' => 'Έιβα']]`** — the application's words as they are
  said, whole words in any case, the longer first. `Speech::speak()` applies them before any
  provider (`Speech::pronounce()`, `Speech::pronunciations()`), and the chat pages hand them to
  `pf-speech-sanitizer.js` through `data-pf-chat-pronounce`, so the browser's voice says them the
  same way instead of transliterating them letter by letter.

## Dictation sends the question when the speaker falls silent

### Changed

- **The chat pages' 🎤** — a silence after something was said sends it, as Enter does. Nothing
  said sends nothing, and the mic pressed again before the silence stops without sending.
- **`pf-voice.js`** — the silence that ends a dictation is 1200 ms rather than 750 (and 500 after
  the speech ended), which cut a question at a breath; `startDictation({silenceMs})` sets another.

## Push notifications for an app on another origin, through the conversation API

### Added

- **`GET {chat}/push/key`, `POST {chat}/push`, `DELETE {chat}/push`** on the conversation API —
  an app signed in with a token (an assistant's PWA on another origin) subscribes to push, as the
  site's pages do through the `Push` controller with their session.
- **`pushsubscriptions.app`** (migration `2026_11_11_000001`) and `Subscriptions::tagApp()` — the
  app a subscription came from. `PushChannel` sends a notification to the subscriptions of the
  app it names (`pushApp($notifiable)`), and one that names none to the site's own, so neither
  reaches the other's devices.
- **`Subscriptions::forUser()` and `exist()`** answer the site's own subscriptions unless asked for
  an app's, or every app's (`Subscriptions::EVERY_APP`): a mass message, a sign-in approval and the
  beacon never reach an app's devices.

## An assistant's tasks, reminders and shares push to its own app's devices

### Added

- **`'llm' => ['chat' => ['app_url' => …]]`** — the assistant of the `chat` space lives in an app
  of its own. A scheduled task run in that space, a calendar reminder and a share made there
  (`RoutineReady`, `TaskReminder`, `SharedWithYou`) push to the app's devices alone, opening the
  app. `Chat\TellsItsApp` carries it; `RoutineReady::tag($notification, $space)` tells a
  notification its space where it can be told.
- **`RoutineReady::channels($notifiable, $app = '')`** — whether `push` belongs in `via()` is asked
  of that app's subscriptions.

## Ask: a question asked aloud is answered aloud — its opening, when it is long

### Added

- **`voice` on a question** — a question dictated on the chat pages is sent with `voice=1`, and
  every way of asking passes it on (`TakesQuestions`). The assistant is told
  (`ContextAssembler::SPOKEN`) to open with one or two plain sentences that stand by themselves.
- **The answer read aloud** — whole when it is short; otherwise its opening paragraph and where the
  rest is: the report it made, or the screen.
- **The person's choice** — the 🔊 box beside the mic. It is kept with their account
  (`answers_aloud`, on by default) by the chat pages' `voicereply` action, on `ChatPageController`
  and `AiController` (`Chat\Web\ReadsAloud`).

## Deploy webhook: two pushes in a row deploy one after the other

### Fixed

- **`WebhookHandler`** ran the deploys of two webhooks seconds apart at the same time — the
  answer goes out before the work — on one shared stage. One's `rm -rf` landed in the other's
  go-live and left `vendor/` half there, and every page answered 500 until the next deploy. Each
  deploy now holds `../.<checkout>-deploy.lock` for its whole list of commands. A second one waits,
  then runs and fetches the newer commit.

## The companion and its debug panel drawn inside a page

### Added

- **`PfCompanion.mount({into})` and `PfCompanionDebug.mount({into})`** draw inside that element, in
  the page's flow, with no fixed corner (`--inline`). In an administration shell, the fixed panel
  fell under the side menu and the dock among the floating buttons. Without `into`, nothing changes.

## An assistant told the part of the day rather than the minute

### Added

- An assistant may answer an optional `clock(Scope)` with `'part-of-day'`: the line before each
  question then says `Now: Wednesday 11 November 2026, night (Europe/Athens).` — morning,
  midday, afternoon, evening or night — instead of the time to the minute. A companion told the
  exact time remarked on it in every conversation. Without the method, or with `'minute'`,
  nothing changes. `ContextAssembler::partOfDay()` gives the part for an hour.

## Ask: a model per person, behind a floor per role, and Automatic within it

### Added

- A new card, **Models people may choose**, on `/admin/Ai/settings` (`Chat\ModelChoices`,
  setting `llm_model_choices`). Each choice has a name, a provider, a model and reasoning on or
  off. It also has a floor: a lowest usertype, or an ability decided by `AdminAccess::allows()`.
- The Ask composer, on the conversation page and the analyst's, draws a picker: **Automatic**,
  then the choices the person reaches, cheapest first. The choice is kept with their account
  (user detail `askmodel`, through the new `modelchoice` action, `Chat\Web\ChoosesModel`) and
  checked again on every question. One that is unknown or above their floor is Automatic.
- Automatic, with two or more choices and `ModelCascade` as the cascade, picks among the
  person's choices: `ModelCascade::choose()` asks the cheapest to name one, in cost order from
  the prices. It never goes above what the role reaches. The pick is held like a tier, and one
  that fails is answered on the cheapest, told so. Without choices nothing changes.

## AI settings: a feature's Model is chosen from its provider's models

### Changed

- On `/admin/Ai/settings` › Features, Model is a list rather than a free text field (FW-416),
  as it already was in each provider's card. It lists the models of the row's provider, or of
  the installation's provider when the row has none, and follows the row's provider when that
  changes. "— (the provider's)" leaves it to the provider, and a saved model in no list stays
  selected. In every theme.

## An assistant may correct its answer before it is stored

### Added

- An assistant may have an optional `polish(Turn $turn, string $answer): string` (FW-417). It is
  called on the finished answer before it is stored, so what the screen, the history and the
  memory keep is the corrected text. `answered()` runs after the store and could not do this.
  It is meant for corrections that are certain in the text alone: a tag moved to the end, "how
  is your day going" at night made "how did your day go". A polish that throws, or answers an
  empty string, leaves the answer as the model wrote it, and the failure is logged.

## The companion inside a page: its full size, and a debug panel that shows what plays

### Fixed

- A dock mounted with `into` (`.pf-companion-dock--inline`) kept the corner's 56×56, so a 64px
  avatar lost its top (an antenna). Inline it now takes the avatar's own size, and the drawing
  may reach past its box. The debug panel's preview was cut the same way and is fixed too
  (FW-418).
- The debug panel's buttons (states, poses, Apply, the activity toggle) showed as bare text
  under a theme's button reset. They now carry `pf-btn pf-btn-sm`. The one playing now is
  `aria-pressed="true"` and drawn in the accent, and it follows `pf-assistant:state` when a
  state ends by itself. Inside the page, the panel is a framed card. In every theme.

## The assistant's picture in every state, on the AI screen

### Added

- `/admin/Ai/avatar` (`AiController::avatar()`, a view in every theme, opened as the settings
  are and linked from them) shows the set in use, large (FW-419). It has a button per state, with
  the one playing marked and handed back to idle by the states that end by themselves, a pose of
  any name, and an Away preview. When the set declares its signals (`avatar_set.moods`, or
  `avatar_moods`), a table lists each signal and the state it plays, with a Try button.

### Fixed

- The companion's dock and debug panel drew with no frame, border or background outside a
  `.pf-ui` element: the theme's tokens (`--pf-line`, `--pf-surface`, `--pf-accent`…) were defined
  only on the framework's screens, so their declarations were invalid at computed time. The dock,
  the panel and the new screen now carry the tokens themselves. This completes FW-418.
- The avatar screen stays in the page's flow, and its buttons draw in the theme's own classes,
  even where an application's copy of `components.css` is older than the screen. Its words have
  their own keys (`Apply the pose`, `Preview away`, `Try it`), so no application's translation
  of a plain "Apply" lands on the pose button.


## After a long gap, the assistant is told how long it has been

### Added

- When a person's last conversation in the same scope and space moved an hour or more ago, the
  line before the question adds `You last spoke with this person 3 days ago. Do not carry on as if
  you had just been talking.` (FW-422). Without it, a companion picked up a conversation from days
  before as if it had just ended. It counts hours under a day, then days. A scheduled answer, or
  one others read, gets no note. `'llm' => ['chat' => ['gap_note' => …]]` sets the threshold in
  seconds (3600 by default), and `0` turns the note off.

## The assistant keeps what it said about itself to each person

### Added

- With `'llm' => ['chat' => ['memory' => ['self' => true]]]` (off by default), the learning pass
  also reads the assistant's replies and keeps, per person, what it made up about itself that
  must stay the same: looks, small details, names, numbers (FW-421). These are memories of kind
  `self`, the first word standing, put into the prompt apart from the person's memories as its own
  word to keep. A companion no longer contradicts itself from one conversation to the next. It
  costs no extra call. New: `Memory::SELF`, `Memory::selfOn()`,
  `Memory::learnConversation($client, $said, $replied)`. `llm:memory-review` skips them.

## The assistant's mood with each person, which lasts and fades

### Added

- `Chat\Mood`, with `'llm' => ['chat' => ['mood' => true]]` (off by default), which takes its words
  from the avatar set's signals, or with `['mood' => ['words' => […]]]` (FW-420). Each answer ends
  with a private `[[mood:word|N]]` tag, which never reaches the stream, the stored answer or the
  history. The conversation keeps the mood. A strong one (60+) colours the person's other
  conversations at four fifths, never anybody else's. It fades by 25 an hour and is not felt under
  15. The next answer is told it as tone, not to be stated.
- The answer's message carries `mood` (`mood`, `intensity`, `plays`), and `GET {chat}/mood`
  answers the person's mood for an idle avatar, or one conversation's with `?conversation_id=`.
- Migration `add_mood_to_chat_conversations`: `mood`, `mood_intensity` and `mood_at` on
  `assist.chat_conversations`.

## Mood and the assistant's word about itself: the conversation page only, unless named

### Changed

- `chat.mood` and `chat.memory.self` apply in the `chat` space only, so the administrators'
  analyst (space `admin`) gets no mood tag and keeps no `self`. `['mood' => ['spaces' => [...]]]`
  and `['self' => ['spaces' => [...]]]` name the spaces. `Mood::on()` and `Memory::selfOn()` take
  the scope to decide.

## Avatar sets with states, poses and transitions of their own

### Added

- An avatar set can declare more than the nine states (FW-424). In `'states'`, a name alone is a
  state of its own, and `name => ms` still makes a state end by itself. `'poses'` lists its poses,
  and `'transitions'` maps `'from>to'` (`*` for any) to a class, or to `[class, ms]`. The picture
  carries `data-states`, `data-poses` and `data-transitions`.
- `pfAssistant.state()` takes a set's own state on the pictures that play it, and puts the
  transition's class on them for its milliseconds as the state changes.
- `AvatarSets::states()`, `poses()`, `transitions()`, and two more optional arguments on
  `register()`.
- `/admin/Ai/avatar` shows every state of the set and a button per pose, to play together.

## A system post signed with a picture as well as a name

### Added

- `SystemPost::post()` takes `avatar` in its options, an http(s) address or a path of this site
  (FW-426). It is kept on the card as `fromAvatar`, and the conversations show it beside the
  message in place of the system's ⚙. A post without one is drawn as before, and an address of
  any other kind is ignored.

## The assistant's mood: its latest word counts, and each answer keeps its own

### Fixed

- In a conversation, the mood is now the model's latest word (FW-427). Before, a weaker,
  different feeling could not displace a stronger one, a rule meant for keyword heuristics: so
  "good night" after good news left the mood happy. A strong mood from another conversation now
  shows only where the conversation has none of its own that is felt.

### Added

- Each answer keeps the mood it was given in, as `extra.mood`, and its message carries `mood` in
  the conversation's history as well as in the answer. With moods on the key is always present,
  `null` when nothing is felt, so an application tells "no mood" from a backend without moods.

## A report's pickers reach its page, for the dimensions it reads

### Fixed

- A custom report's dimension pickers never reached its page (FW-428). They were written into
  the view one element at a time, which a view's own property does not keep: a notice in
  development and no pickers in production.
- A dimension's values given as a closure were read again by every card of a report, which for
  a dimension of thousands read from the database meant a query per card. They are now read once
  and kept for a minute (`Dimension::KEEP`).

### Changed

- A report offers a picker only for the dimensions it reads (`Report::dimensions()`: what its
  rows, columns and cards filter on or break down by), or that the address sets. A dimension of
  more than 50 values is a search field rather than a list. Both apply in every theme.

## Read aloud: each part told as it is heard, for subtitles

### Added

- `pf-voice.js`: `speak(id, text, { onPart })` calls `onPart({index, count, text})` as each part
  starts to be heard, so a page can show an answer as subtitles in step with the voice. With the
  speech server the parts are its sentences. The browser's voice reads everything as one part.
- `opts.parts` passes the caller's own pieces of the original. Each is said cleaned and told back
  as given, so the subtitles show the original words, not the transliteration that was spoken.

## Tesla, a character the framework ships

### Added

- `Assist\Characters`: characters an application can use as they are. The first is Tesla, a
  slate-grey cat with a white heart on her chest and white front socks (FW-425). Her art came
  from one application's own component and is now shared, so no application keeps a copy.
  `'avatar_set' => 'tesla'` draws her. She has twelve poses, fourteen states of her own, the
  transitions between them, four gaits, a mirrored facing and pupils that look where
  `--pf-look-x/y` say. All of it is one svg and a plain stylesheet, without a framework.
- `Characters::get('tesla')`: her name, gender, a prompt saying who she is, a dock size and her set.
- `AvatarSets::moods()`: what each mood word plays. The moods of a set given in app.php come
  first, then `analyst.avatar_moods`, then the set in use's own. `Mood::plays()` and the AI
  screen read it, so her moods are the words the model may use when moods are on.
- `{uid}` in a set's markup is different in each picture drawn, for its gradients' ids.
- A set's `css` that is a file on disk is written into the page as a `<style>`, once.

## The assistant picks what it does and wears in an answer; a person keeps a style

### Added

- `Chat\Acts` (FW-430). An avatar set's `acts` (word → what it plays, and when) and `wear`
  (word → a pose, and when) are offered to the model in the conversation page. An answer may end
  with `[[act:…]]` and `[[wear:…]]`. The tags are taken out like the mood's. The message and the
  history carry `act` = `{act, plays}` and `wear` = `{wear, pose}`, null when none was chosen.
- `GET/PUT {chat}/style`: the person's style, a pose of the set's kept with their account
  (`askstyle`). An answer's wear covers it for that answer.

### Fixed

- The AI screen's preview of the assistant's picture has room around it (48px above and below,

## The web is the conversation page's, not the analyst's, unless named

### Changed

- `'llm' => ['chat' => ['web' => true]]` offers `web_search` and `fetch_url` in the `chat` space only

- Personal data does not leave by an address. A tool may say which argument it sends out

## A mood from another conversation fades instead of feeding itself

### Fixed

- A strong mood reached the person's other conversations as `Your mood right now: excited`. The
  model said it back, it was kept as the new conversation's own, and it reached the next one, so

## Personas: more than one character on the conversation page

### Added

- `Chat\Personas` (FW-423): `'llm' => ['chat' => ['personas' => [...]]]`. One persona is the
  default, and a persona may be a framework character (`'character' => 'tesla'`). Each keeps its
  own conversations, memories, word about itself, mood, queued questions and tasks, stored under
  `chat:<persona>`. The default writes plain `chat`, so existing data stays the default's. The
  profile, calendar and journal are shared. A persona other than the default is told who it is.
  It may name its own assistant class and a feature (its model). Its moods, acts and wear come
  from its own avatar set.
- `Scope` takes a persona: `stored()`, `person()`, `withPersona()`, and a stored space

- `GET {chat}/personas` (with each persona's picture) and `PUT {chat}/persona`; the choice is kept
  in `askpersona`. The style of FW-430 is kept for each persona apart.
- `AvatarSets::using($set, $run)`: another set in use for a while, such as a persona's.

## Dictation by a server, where the browser recognises no speech

## A queued answer followed as a stream

### Added

- `GET {chat}/asks/{id}/stream` (FW-438): Server-Sent Events for a queued question. It sends
  `doing` as it changes, `partial` up to the last whole sentence with tags already out, then
  `answered` with the stored answer's id, content, mood, act, wear and `ended`, or `failed`, and
  closes. A voice can start reading as soon as the first sentence is whole.
  `Asks::follow($scope, $id, $emit)` is the loop behind it, and `Asks::wholeSentences()` is how
  a sentence counts as ended.

## A question is not a fact, an alarm is looked up, and an answer before a tool is the answer

## Seeing a companion's person, and resetting their experience
