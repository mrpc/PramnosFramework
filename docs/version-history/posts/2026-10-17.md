## The authorization server and the public MCP endpoint, from the first installation to switch them on

FW-153.

### Fixed

- **The MCP endpoint accepted the API's own sign-in JWT.** The API's middleware identifies a
  caller from any token it signed, the sign-in token (`tokentype` `auth`) included, and the
  endpoint took that as a credential. A bearer now has to be an access token, issued by the
  authorization server or `mcp:token`; anything else gets the discovery `401`. A call with no
  bearer (a same-origin session) is unaffected.
- **`mcp:token` signed with the console application's key and printed `sURL/mcp`.** The endpoint
  is an API route, verified with the API's key under `/<api>/<version>/mcp`, so the token answered
  `401`.
    - It now signs with the API's key and prints that address. `--url` is the API's base.
    - It adds a `jti`, so two tokens minted in one second no longer collide.
    - It refuses, saying to widen the column, when `usertokens.token` is too short for the
      encrypted token. An older `varchar(255)` cut it without a word.
- **The authorization server no longer makes its signing keys mid-request.** A pair made that way
  belonged to the web server's user, was never backed up, and a new container made a new one.
    - Missing keys now fail with the command to run, in the `oauth` log and in the
      `signing_keys` health check.
    - A key the process cannot read says whose it is.
    - `oauth:keys` also makes `encryption.key` once, takes `--owner=<user>`, and warns when run as
      root without it.
- **Discovery named the authorization server two ways.** `issuer` was `https://host/` and
  `authorization_servers` was `["https://host"]`. A strict client compares them and refuses the
  pair. Both now come from `Discovery::issuer()`, with the trailing slash that relying parties
  already compare `iss` with.
- **`ApplicationService::create()` and `update()` failed on an older `applications` table.**
  - They wrote `broadcast_secret`, which that table lacks.
  - They wrote NULL into `NOT NULL` columns with no default.
  - They now write only the columns that exist, with `''` or `0` where NULL is refused.

### Changed

- **`/.well-known/health` answers `status` and 200/503 publicly.** The `components` map, which
  names what is failing, appears only with `'health' => ['public_details' => true]`.
- **The consent screen is translated.** Its words, the scope categories and every scope
  description go through `t()`, the MCP scopes' included.

### Added

- **`SchemaBuilder::columnLength($table, $column)`**: the most characters a column holds, 0 for
  none. `ApplicationService::callbackCeiling()` uses it.

### Documentation

- The MCP, AuthServer Integration, Health, Console and Schema Builder guides describe the above.
