## The analyst's download link, from the queue worker

### Fixed

- `export_csv` runs in the queue worker. There `SiteUrl` read the console's stand-in request —
  `HTTP_HOST=localhost` and the script's directory — and the link came out as
  `http://localhostbin/Ai/export/…` on every installation without `APP_URL`.
    - The console now marks the request it invents (`PRAMNOS_CONSOLE_HOST`), and `SiteUrl`
      answers `''` for it, as it already did for a console with no request at all.
    - Without a site root, `Exports::url()` builds the link from the host's root
      (`/admin/Ai/export/…`).
    - `Markdown::toHtml()` links a path from the site's root, in the same tab. `//host` and
      `/\host` stay text.
- The `site_url` health check says, while exports are on, that their links need it.

### Documentation

- LLM Guide, *Its own SQL, and files to download*. Upgrade Guide: one row.

## A side panel on every administration page: Ask about it, and its help

### Added

- The admin header's **Ask** opens a panel beside the page, with two tabs:
    - Ask is the analyst, about this page. A question carries the screen, the action, the
      address, the title, and the record the page shows.
    - Help is the page's help.
- Without the analyst the button is *Help*; with neither, there is no button. The panel is drawn
  by `Analyst::headerButton()`, so every scaffolded header has it. It keeps its tab and
  conversation from page to page.
- `Assist\Page`: the request's first controller is recorded by `Controller::exec()`.
    - `protected string $assistSubject` says what one record of a screen is; the framework's
      screens declare theirs.
    - `Page::about()` names a record from an action.
    - `Page::fromInput()` checks what comes back from the browser.
    - `Page::prompt()` is what the analyst is told.
- `Assist\Help`, the help pages:
    - files in `app/help/**/*.md` (or `'help' => ['paths' => …]`), before the framework's
      `resources/help/`, which ships a page for each of its screens;
    - front matter: `title`, `section`, `questions` and `updated`;
    - `help:` links between pages, and pictures beside them;
    - a search that folds Greek accents and the final sigma, and compares the first five letters.
- `/admin/Help` (`HelpController`, scaffolded as `src/Admin/Controllers/Help.php`): the pages by
  section, a search, one page, and its pictures. The menu item appears where the wrapper exists.
- The analyst's `help` tool answers from the pages, with their links.
- `Markdown::toHtml($text, ['link' => …, 'image' => …])` resolves links that are not `http(s)`,
  and pictures.
- `pf-chat.js`:
    - `window.PfChat.init(element)` runs a conversation placed later;
    - `pf-chat:ready` is fired after each drawing;
    - `data-pf-chat-embedded` leaves the address bar alone.

### Documentation

- New guide: *Administration help and the side panel*. LLM Guide: *From any administration
  page*. Upgrade Guide: one row.

## The examples go as soon as a question is sent

### Fixed

- `pf-chat.js` left the example questions on screen until the answer arrived. They are hidden as
  the question is sent, by the button or Enter, and come back with it when it is refused.

## The analyst's links go where the question was asked

### Fixed

- The queue worker runs the site's application, which has no admin area configured, so an export
  link came out as `/Ai/export/…` — the site's home page.
    - The question now carries the area's URL as its request saw it (`Desk::extra()`, `area`).
    - The analyst's `export_csv` and `help` tools build their links under it: absolute, in the
      area, with no setting.

### Added

- `AdminArea::address($path, $base)`: an address in the area from a job. It uses the given base,
  else the area's URL inside it, else the configured prefix under the site root.
- `Exports::url()`, `Help::url()`, `Analyst::tools()`, `mcpTools()`, `ExportCsvTool` and
  `HelpTool` take the area's URL.

## The analyst's scoped tools on MCP as well

### Added

- `McpServiceProvider::registerDefaults()`, and so `mcp:serve`, serves the application's tools:
    - every entry of `'mcp' => ['tools' => [...]]`;
    - those of `'llm' => ['admin_tools' => [...]]` that implement `ScopedMcpTool`, to tokens
      holding the scope. An unscoped analyst tool stays Ask's.
    - `McpServiceProvider::applicationTools()` lists them. A framework tool keeps its name.

### Documentation

- MCP Guide, *A tool*. LLM Guide: the analyst's tools and links. Upgrade Guide: one row.

## `Pagination` says each link's page for a script

### Added

- Every `Html\Pagination` link carries `data-page="N"`, the page it goes to: the numbered links,
  and first, previous, next and last with the page each leads to. It comes last among the link's
  attributes. A script reads `link.dataset.page` instead of parsing the `href`. Without it, the
  pager's handlers read the removed `alt` and asked for `/page/undefined`.

### Documentation

- HTML Components Guide, *Pagination*: reading the page from a script.

## The examples go on Bootstrap too

### Fixed

- The examples' row is laid out with an inline `display:flex`, and `[hidden]` loses to it, so on
  Bootstrap they stayed on screen after a question was sent. `pf-chat.js` hides them by their own
  `display` and puts it back for a refused question. The side panel hides Ask's list and settings
  the same way. Checked in Chromium against the Bootstrap view.

## Help pages are a feature

### Changed

- `help` is registered in `FeatureRegistry`. With it the side panel has its Help tab, `/admin/Help`
  and its menu item answer, and the analyst has the `help` tool and reads a page's help. Without
  it the panel is Ask alone and `HelpController` answers 404. `Help::enabled()` says which.
- `init` turns it on in a new project without asking, and writes `src/Admin/Controllers/Help.php`
  only with it. `--features=…` lists it like the others.

### Documentation

- Administration help and the side panel: *The `help` feature*. Upgrade Guide: one row.

## The side panel's conversation runs once, and the application's help page comes first

### Fixed

- The panel placed the conversation and then loaded `pf-chat.js`, whose own start found it; the
  panel then ran it a second time. Every button — *Copy table* most visibly — and every listener
  was there twice. `init()` now runs once per drawing (`data-pf-chat-ready`); a conversation
  swapped in after an answer is a new drawing.
- `Help::forScreen('users', 'edit')` took the framework's `users/edit.md` over an application's
  `users.md`. The application's page wins now, whichever of the two it wrote.

## Each request's own page, where one process serves many

### Fixed

- `Assist\Page` keeps the request's first controller, and nothing cleared it between requests in
  one process. Under `TestClient`, a page requested after `/admin/Ai` was still the `ai` screen,
  so its panel was the plain Ask link. `Application::beginRequest()` resets it with the admin
  area, for a web request and for each `TestClient` request alike.

## Nothing offers the AI until there is a key

### Changed

- Without a provider's key every question fails, so nothing invites one:
    - *Ask AI* is left out of the user menu, and the chat widget draws nothing;
    - the admin header has no Ask, and the side panel no Ask tab;
    - `/admin/Ai` opens the settings, where the key is set. The admin menu's *AI* item stays.

### Added

- `Chat::available()` (with the asking person's routing) and `Analyst::available()`.
- `NavItem`'s `when:`, a closure asked each time the menu is drawn; an item is hidden while it
  answers false or throws.

### Documentation

- LLM Guide, *The administrators' analyst*. Administration help and the side panel. Upgrade
  Guide: one row.

## A geometry value cannot leave its literal

### Fixed

- **Security.** `Database::insertDataToTable()` and `updateTableData()`, on PostgreSQL, put a
  `geometry` value that is not a `lat, lon` pair between the quotes of `ST_GeomFromText('…')` as
  it came. A `'` in it ended the literal, and the rest ran as SQL — from a form field or an API
  body. The quote is now doubled. A `['latitude' => …, 'longitude' => …]` array's values are cast to
  numbers.

## Every guide checked against the code

### Documentation

- Every guide was read against the code it describes, and corrected where they disagreed: examples
  calling methods that do not exist or with the wrong arguments (the Routing, API, Schema
  Builder, ORM, Testing, Theme, Logging and Document Output guides most), settings and options
  that nothing reads, wrong defaults, and broken anchors. History in a guide's prose — dates,
  "used to", incident stories, comparisons with removed classes — is gone; the current
  behaviour and its reasons stay. `Roadmap.md` keeps only open items.

## A generated model loads

### Fixed

- `create:crud` / `create:model` wrote `save($autoGetValues = false, $debug = false)` with no
  return type, and `OrmModel::save()` declares `: static`, so a generated model was a fatal at
  class load. The stub declares `: static` and returns `$this`. The generator's test now loads the
  class it writes, not only lints it. Upgrade Guide: one row.

## The webhook provider reads its documented configuration

### Fixed

- `WebhookServiceProvider` read settings named `webhook.secret` and so on, which the documented
  `'webhook' => [...]` block in `app.php` never is; the handler was not built ("secret must not
  be empty"). It reads the block, and a setting answers where the block has no such key. An unset
  log channel is `webhook`, not an empty string.
