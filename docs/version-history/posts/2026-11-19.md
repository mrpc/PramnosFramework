# 19 November 2026

Four entries today:

- The export modal's two radio pairs now carry a group label each (FW-534)
- The export modal keeps a fixed title and size across every state (FW-535)
- `NotificationBell` can link to the notification preferences page (FW-536)
- `Xlsx::write()` writes `[Content_Types].xml` as the ZIP's first entry (FW-537)

<!-- more -->

## The export modal's two radio pairs now carry a group label each (FW-534)

### Fixed

The "All filtered rows"/"Current page only" scope radios and the "All columns"/"Selected
columns" radios (FW-533) rendered as one unbroken block with nothing marking where the first
pair ends and the second begins — reported after an owner read all four as one
mutually-exclusive group instead of two independent decisions (which rows, which columns). A
small bold label — "Rows" above the scope radios, "Columns" above the columns radios — now
sits above each pair.

### Documentation

`docs/Pramnos_Html_Components_Guide.md`'s "Selected columns" vs "All columns" paragraph now
mentions the group labels.

## The export modal keeps a fixed title and size across every state (FW-535)

### Fixed

What looked like the modal's title ("Export") was actually the format `<select>`'s own
`<label>`, living inside `.pf40-export-controls` — so it disappeared along with the rest of
the controls the moment "Start export" switched the modal to `.pf40-export-progress`. The
modal was then left with no heading at all, just the progress text and the close button,
which an owner read as a different, smaller dialog rather than the same one changing state.
The title is now its own element, outside both `.pf40-export-controls` and
`.pf40-export-progress`, rendered once and visible through controls, progress, and a failure
alike. The format `<select>` gets its own "Format" label in its place. The modal's inner box
also carries a `min-width`/`min-height`, so it stops visibly shrinking when the controls give
way to a shorter progress message.

### Documentation

`docs/Pramnos_Html_Components_Guide.md`'s export modal section now describes the fixed
title and the inner box's minimum size.

## `NotificationBell` can link to the notification preferences page (FW-536)

### Added

`NotificationBell::render()` takes two new options, `settingsUrl` and `settingsLabel`
("Notification settings"). Given `settingsUrl`, a gear icon next to "mark all read" links
there — any application that already declares `notifications.types`/`Preferences` (FW-488)
has a settings page, but nothing in the bell pointed at it before now. Neither option is
required; without `settingsUrl` the panel renders exactly as before.

### Documentation

`docs/Pramnos_Notifications_Guide.md`'s `NotificationBell::render()` example and option list
now cover `settingsUrl`/`settingsLabel`.

## `Xlsx::write()` writes `[Content_Types].xml` as the ZIP's first entry (FW-537)

### Fixed

`Xlsx::write()` added `xl/worksheets/sheet*.xml` before `[Content_Types].xml`, so the ZIP's
first entry was a worksheet, not the content-types part. Every XML part was individually
well-formed, but the OPC spec requires `[Content_Types].xml` to be the package's first
entry, and Excel enforces it strictly — opening a file written this way produced "We found
a problem with some content" and offered to recover it. `[Content_Types].xml` is now
written before any worksheet.
