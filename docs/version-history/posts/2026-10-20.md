## The sso and registration headings, and two second-factor messages, in the site's language

### Fixed

- **The sso and registration pages had English headings on a Greek site.** `Account` handed
  their views `'Single Sign-On'` and `'Create Account'` as literals, and the views print
  `$this->header` as given. The two success messages `TwoFactorAuth` hands its views ("New backup
  codes generated…", "Two-factor authentication has been enabled successfully!") were English
  the same way. All four go through `t()`, and the Greek catalogue has them.

## A page that prints the time is cached again

### Fixed

- **Yesterday's check for the visitor's id in a stored page refused every page that printed
  `time()`.** It looked for the value of each tracking cookie the response set, and `lastseen`
  holds `time()`. So a page whose script printed the current time, or a cache-buster, matched it
  within the same second, and was never stored for a visitor without cookies: every bot and
  every first visit. One application lost the cache on its second page by search traffic. A
  value of digits only is no longer looked for. A timestamp identifies nobody; the visitor id is
  hexadecimal.
