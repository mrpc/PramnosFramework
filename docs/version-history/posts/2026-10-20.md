## The sso and registration headings, and two second-factor messages, in the site's language

### Fixed

- **The sso and registration pages had English headings on a Greek site.** `Account` handed
  their views `'Single Sign-On'` and `'Create Account'` as literals, and the views print
  `$this->header` as given. The two success messages `TwoFactorAuth` hands its views ("New backup
  codes generated…", "Two-factor authentication has been enabled successfully!") were English
  the same way. All four go through `t()`, and the Greek catalogue has them.

## A page that prints the time is cached again

### Fixed

- **Yesterday's check for the visitor's id in a stored page refused every page that printed
  `time()`.** It looked for the value of each tracking cookie the response set, and `lastseen`
  holds `time()`. So a page whose script printed the current time, or a cache-buster, matched it
  within the same second, and was never stored for a visitor without cookies: every bot and
  every first visit. One application lost the cache on its second page by search traffic. A
  value of digits only is no longer looked for. A timestamp identifies nobody; the visitor id is
  hexadecimal.

## A migration reaches the long-running workers

A migration run without a deploy, or after the deploy's restart (the request that runs pending
migrations comes later), left every worker on the old schema: the tables `hasTable()` had found,
its models' column lists, its prepared statements. The orchestrator restarted daemons on a new
commit, and a migration changes none.

### Added

- **`MigrationRunner::schemaGeneration()`**: an opaque token in `var/schema-generation` that
  moves whenever a batch applies or rolls back anything, and not when nothing was pending.
- **`DaemonOrchestrator`** compares it on the same timer as the git hash and restarts its daemons
  when it moves, printing `[schema] Migrations changed the schema`.
- **`CommandBase::shouldStop()`**, asked between tasks by every worker loop, forgets the tables
  and columns it found when the generation has moved.

### Fixed

- **A table dropped by another process stayed "found".** A query that fails because the table is
  not there (MySQL 1146, PostgreSQL 42P01), raw or through the builder, makes the connection
  forget what `hasTable()` and `hasColumn()` remembered. The process is wrong once and right
  from then on.

## `prepareQuery()` on PostgreSQL reads a `DATE_FORMAT` pattern written for printf

### Fixed

- **``prepareQuery("SELECT DATE_FORMAT(`created`, '%%Y-%%m') … WHERE `email` = %s", $email)``
  threw `ValueError: Unknown format specifier "Y"` on PostgreSQL.** The MySQL translation ran
  before printf, and read `%%Y` as MySQL would: a literal percent, then a `Y`. It kept that as
  text, and printf then met `%Y`. `prepareQuery()` now has the pattern read with `%%` as `%`, and
  the `to_char` pattern that comes out keeps any literal percent doubled for printf. The same
  call gives `to_char(…, 'YYYY"-"MM')` and the address in its place. Reported by an application
  moving to PostgreSQL (FW-179).

### Documentation

- The Database API Guide says how a `DATE_FORMAT` pattern is written through `prepareQuery()`.

## A schema is no longer glued to the word before a backticked name on PostgreSQL

### Fixed

- **``insert into`#PREFIX#t`(`a`) values (1)`` — valid MySQL, no space before the name — became
  `insert intopublic."t"(…)` on PostgreSQL**, a syntax error at "intopublic". `prepareQuery()`
  and `prepare()` put the schema in front of the quoted name and nothing between it and the word
  before. A space goes there now, before `from`, `join`, `update` and the rest alike (FW-180).

## The query builder quotes a qualified mixed-case column on PostgreSQL

### Fixed

- **`whereNull('u.registrationStatus')` failed on PostgreSQL with "column u.registrationstatus
  does not exist".** The builder quoted a bare mixed-case column, so PostgreSQL would not fold
  it, but a qualified one only when it was a reserved word. The column of `table.column` now
  follows the bare name's rule, in every place the builder names a column. The table or alias in
  front is still quoted only when it is a reserved word. One application has 79 such columns
  (FW-181). The Upgrade Guide has the row.
