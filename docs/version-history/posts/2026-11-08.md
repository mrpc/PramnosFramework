## Skills from catalogues, installed for the whole application from the AI settings

### Added

- **Skills** in the AI settings (`Ai/skillcatalog`): search the catalogues, read a skill before
  installing it (method, references, evals, licence, commit, what is left out), and install it into
  the database for the whole application, where a deploy does not remove it
  (`Pramnos\Llm\Chat\CatalogSkills`, `Web\KeepsCatalogSkills`). It is installed off and turned on
  by somebody who manages skills. A newer version is shown with its diff and is never taken by
  itself. Once taken, the skill is off again. Scripts are never taken. Turning a skill on or off,
  limiting it to a role, updating and deleting are recorded in the audit log with the commit.
- Ask is offered these skills as `catalog:<name>`: to everybody who has Ask or to a role and up,
  with their references read from the database. A skill file of the same name wins.
- `skill:list` lists them after the files.
- Migration `2026_11_08_000001_add_catalogue_columns_to_chat_skills`: `source`, `source_commit`,
  `content_hash`, `licence` and `files` on `pramnos.chat_skills`.

### Why

`skill:add` writes into the skills folder, which is the repository's. Taken on a production server,
a skill would be removed by the next deploy.

See [Tools — Skills from catalogues, installed from the AI settings](../../Pramnos_LLM_Tools_Guide.md#skills-from-catalogues-installed-from-the-ai-settings).

## Ask's gear leads to the application's skills

### Added

- Ask's gear has *The application's skills* (Greek: *Τα skills της εφαρμογής*) right after *My
  skills*, for whoever manages skills. Before this, the page could be reached only from the AI
  settings. The analyst page passes the link as `urls['skillcatalog']`, empty for anybody else.

## The Ask screens keep their layout in an administration on Bootstrap 3

### Fixed

- The `bootstrap` theme's Ask screens (`Ai/settings`, `Ai/skillcatalog`, `Ai/skills`,
  `Ai/memories`, `Ai/scheduled`, `Ai/all`, `Ai/reviews`, a review, a call, Ask) ran off the right edge
  in an administration on Bootstrap 3. They used `.container`, which is 1170px wide there, and
  Bootstrap 5's `d-flex`, `gap-*`, `card-body` and `form-select`, which do not exist in Bootstrap 3:
  cards had no padding and a select shrank to a 20px strip. Each screen now prints the framework's
  layout rules (`Pramnos\Theme\NeutralLayout`, `pf-l-*`) and uses only the classes both versions
  share.
- *My skills*: a long tool name no longer runs over the next column of the tool grid. It breaks
  after each `_`, not in the middle of a word. This applies in every theme.
- The application's skills page (`Ai/skillcatalog`) is in Greek.

See [UI systems — The framework's screens under an older Bootstrap](../../Pramnos_Theme_UI_Systems_Guide.md#the-frameworks-screens-under-an-older-bootstrap).

## A template updated by composer is compiled again; `view:clear`

### Fixed

- A compiled template (`var/viewcache/`) was kept while it was *newer* than its `.tpl.php`.
  Composer unpacks a package with the times of its commit, so after an update a bundled view was
  often older than the file compiled from the version before it, and the old screen went on being
  served, without an error, until somebody deleted the cache. A compiled file now carries its
  template's time and is used only while the two are the same (`TemplateCache`). Any other time,
  older or newer, compiles it again.

### Added

- `view:clear`: deletes the compiled templates.

See [Themes — Compiled once, again when the template changes](../../Pramnos_Theme_Guide.md).
