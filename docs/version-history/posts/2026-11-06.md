## Metrics: a catalogue of the business's numbers, computed per period and kept

### Added

- **`Pramnos\Metrics`**: applications declare their numbers once, in a catalogue that app.php
  lists (`'metrics' => ['catalogue' => [...]]`), and reports, dashboards and the assistant read
  the kept values instead of working them out again on each page.
  - **Kinds:** `Metric::flow()` counts what happened in a period. `Metric::level()` keeps how
    things stood when the period closed. `Metric::derived()` is arithmetic over other metrics,
    worked out when read.
  - **Sum or distinct:** `Metric::SUM` breakdowns add up. A `Metric::DISTINCT` metric, such as
    unique customers, is counted on its own at every grain and every breakdown it keeps, so a
    month is never its days added together.
  - **Dimensions:** declared once with `Dimension::of()` and shared by every metric that names
    them.
- **`stats.metric_values`** (`stats_metric_values` on MySQL) keeps one value per metric, grain
  (day, week, month, quarter, year), period and breakdown. It is in a new schema, `stats`, for
  the business's figures.
  The table is plain by default. Its primary key `(metric, grain, period_start, dims_hash)` holds
  the time column, so an installation can make it an uncompressed hypertable on `period_start`
  through app.php's `hypertables` and `timescale:ensure`. The guide explains why there are no
  continuous aggregates over the values.
- **`metrics:compute`** computes the open periods and **closes** each period once after it ends.
  A closed period is kept unless `--recompute` asks for it again, and a level never is. Rows are
  never written for a period that has not begun. The framework's schedule runs it hourly, and it
  does nothing where no metric is declared. With `'replica' => true`, sources read the replica.
- **Reading and history:** `Metrics::series()`, `value()`, `compare()` (with the previous period,
  or the same period a year earlier) and `records()` (the rows behind a number) read the values.
  `Metrics::import()` keeps history that cannot be computed again.

### Documentation

- New guide: [Metrics](../../Pramnos_Metrics_Guide.md).

## Metrics on the dashboard and for the analyst

### Added

- **A dashboard card for each metric**, `metric.<name>`. It is offered to those the metric
  allows and is off a new dashboard. One period draws a tile with an optional comparison (the
  period before, or a year earlier). Several periods draw a chart, broken down by a dimension and
  filtered. `'dashboard' => ['metrics' => false]` leaves the cards out.
- **The analyst's `metrics` tool**, present where the application declares metrics. It answers
  the catalogue, a series, a comparison and the records behind a number, only for the metrics
  the administrator may see.

### Documentation

- [Metrics](../../Pramnos_Metrics_Guide.md), [Dashboard](../../Pramnos_Dashboard_Guide.md#metric-cards)
  and [Analyst](../../Pramnos_LLM_Analyst_Guide.md).

## Reports built from metrics

### Added

- **`Pramnos\Metrics\Report`**: sections of rows across columns.
  - **Columns** are a list of specs: each a label, filters, an optional metric of its own and a
    period offset. `['periods' => N]` and `['dimension' => …, 'total' => true]` are shorthands.
  - **Cells** are the row's metric with the row's and the column's filters together.
  - **Rows** can stand for one row per value of a dimension (`breakdown`), with a total that is
    the metric without the breakdown, so a distinct total is counted, not added.
  - **Extras:** a comparison with the previous period or a year earlier, a chart per section and
    section totals.
  - **Output:** HTML with cells linking to the records behind them, and CSV.
  - **Reading:** rows of metrics the reader may not see are left out and counted. A cell that
    cannot be answered says why, and the rest of its row stands.
- **`Pramnos\Metrics\Reports`** and **`stats.reports`**: ready reports from app.php
  (`'metrics' => ['reports' => [...]]`) and saved ones, shared like dashboard presets and mailed
  daily, weekly or monthly.
- **`/admin/MetricReports`** (the *Reports* menu item, where metrics are declared): a period
  picker, CSV, print or save as PDF, the records behind a cell, and an editor that writes columns
  and sections as text. Its views are the first framework views written as `.tpl.php` templates
  in the framework's template engine.
- **`metrics:reports-send`** mails each scheduled report once a period closes, as its owner sees
  it, through the outbox. It runs daily at 07:30 in the framework's schedule.
- **`data-pf-print`** in `pf-utils.js` prints the page, since an inline `onclick` is refused by
  the CSP.

## `Model::_save()` lets a NOT NULL number with a default take it

### Fixed

- **A `NOT NULL` numeric column with a default, left null by the model, failed every save.**
  - **What happened:** `Model::_save()` coerced the null to `''`, which reached the database as
    NULL, so `credit DECIMAL(12,2) NOT NULL DEFAULT 0` refused the insert.
  - **The fix:** such a column is now omitted from the write, as a `NOT NULL` date already was.
    An insert takes the column's default, and an update keeps the stored value.
  - **Unchanged:** text columns and numbers without a default still take `''`.
  - **Behind it:** the PostgreSQL column introspection reads `column_default`.
