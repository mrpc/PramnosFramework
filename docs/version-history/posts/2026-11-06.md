## Metrics: a catalogue of the business's numbers, computed per period and kept

### Added

- **`Pramnos\Metrics`**: applications declare their numbers once, in a catalogue that app.php
  lists (`'metrics' => ['catalogue' => [...]]`), and reports, dashboards and the assistant read
  the kept values instead of working them out again on each page.
  - **Kinds:** `Metric::flow()` counts what happened in a period. `Metric::level()` keeps how
    things stood when the period closed. `Metric::derived()` is arithmetic over other metrics,
    worked out when read.
  - **Sum or distinct:** `Metric::SUM` breakdowns add up. A `Metric::DISTINCT` metric, such as
    unique customers, is counted on its own at every grain and every breakdown it keeps, so a
    month is never its days added together.
  - **Dimensions:** declared once with `Dimension::of()` and shared by every metric that names
    them.
- **`stats.metric_values`** (`stats_metric_values` on MySQL) keeps one value per metric, grain
  (day, week, month, quarter, year), period and breakdown. It is in a new schema, `stats`, for
  the business's figures.
  The table is plain by default. Its primary key `(metric, grain, period_start, dims_hash)` holds
  the time column, so an installation can make it an uncompressed hypertable on `period_start`
  through app.php's `hypertables` and `timescale:ensure`. The guide explains why there are no
  continuous aggregates over the values.
- **`metrics:compute`** computes the open periods and **closes** each period once after it ends.
  A closed period is kept unless `--recompute` asks for it again, and a level never is. Rows are
  never written for a period that has not begun. The framework's schedule runs it hourly, and it
  does nothing where no metric is declared. With `'replica' => true`, sources read the replica.
- **Reading and history:** `Metrics::series()`, `value()`, `compare()` (with the previous period,
  or the same period a year earlier) and `records()` (the rows behind a number) read the values.
  `Metrics::import()` keeps history that cannot be computed again.

### Documentation

- New guide: [Metrics](../../Pramnos_Metrics_Guide.md).

## Metrics on the dashboard and for the analyst

### Added

- **A dashboard card for each metric**, `metric.<name>`. It is offered to those the metric
  allows and is off a new dashboard. One period draws a tile with an optional comparison (the
  period before, or a year earlier). Several periods draw a chart, broken down by a dimension and
  filtered. `'dashboard' => ['metrics' => false]` leaves the cards out.
- **The analyst's `metrics` tool**, present where the application declares metrics. It answers
  the catalogue, a series, a comparison and the records behind a number, only for the metrics
  the administrator may see.

### Documentation

- [Metrics](../../Pramnos_Metrics_Guide.md), [Dashboard](../../Pramnos_Dashboard_Guide.md#metric-cards)
  and [Analyst](../../Pramnos_LLM_Analyst_Guide.md).

## Reports built from metrics

### Added

- **`Pramnos\Metrics\Report`**: sections of rows across columns.
  - **Columns** are a list of specs: each a label, filters, an optional metric of its own and a
    period offset. `['periods' => N]` and `['dimension' => …, 'total' => true]` are shorthands.
  - **Cells** are the row's metric with the row's and the column's filters together.
  - **Rows** can stand for one row per value of a dimension (`breakdown`), with a total that is
    the metric without the breakdown, so a distinct total is counted, not added.
  - **Extras:** a comparison with the previous period or a year earlier, a chart per section and
    section totals.
  - **Output:** HTML with cells linking to the records behind them, and CSV.
  - **Reading:** rows of metrics the reader may not see are left out and counted. A cell that
    cannot be answered says why, and the rest of its row stands.
- **`Pramnos\Metrics\Reports`** and **`stats.reports`**: ready reports from app.php
  (`'metrics' => ['reports' => [...]]`) and saved ones, shared like dashboard presets and mailed
  daily, weekly or monthly.
- **`/admin/MetricReports`** (the *Reports* menu item, where metrics are declared): a period
  picker, CSV, print or save as PDF, the records behind a cell, and an editor that writes columns
  and sections as text. Its views are the first framework views written as `.tpl.php` templates
  in the framework's template engine.
- **`metrics:reports-send`** mails each scheduled report once a period closes, as its owner sees
  it, through the outbox. It runs daily at 07:30 in the framework's schedule.
- **`data-pf-print`** in `pf-utils.js` prints the page, since an inline `onclick` is refused by
  the CSP.

### Documentation

- [Metrics](../../Pramnos_Metrics_Guide.md#reports), [Console](../../Pramnos_Console_Guide.md).

## `Model::_save()` lets a NOT NULL number with a default take it

### Fixed

- **A `NOT NULL` numeric column with a default, left null by the model, failed every save.**
  - **What happened:** `Model::_save()` coerced the null to `''`, which reached the database as
    NULL, so `credit DECIMAL(12,2) NOT NULL DEFAULT 0` refused the insert.
  - **The fix:** such a column is now omitted from the write, as a `NOT NULL` date already was.
    An insert takes the column's default, and an update keeps the stored value.
  - **Unchanged:** text columns and numbers without a default still take `''`.
  - **Behind it:** the PostgreSQL column introspection reads `column_default`.

## A view of either kind: `display()` finds a `.tpl.php` too

### Fixed

- **A view written only as `.tpl.php` was drawn blank.** A `display()` that asked for HTML
  looked only for `.html.php`, and said nothing when it found none.
  - **Now:** at each place a template may be (the theme's override, the application's view
    directory, the bundled scaffold), the kind asked for is tried first and the other kind next.
  - **Overrides are kept:** an application's own `.html.php` of a view still wins over a bundled
    `.tpl.php`, so bundled views can move to the template engine without losing anybody's
    override.

### Documentation

- [Theme guide](../../Pramnos_Theme_Guide.md): the view lookup, with both kinds.

## The bundled views move to the template engine

### Changed

- **Every view the scaffold bundles is now a `.tpl.php` template** in the framework's template
  engine, in all three themes. The themes' layout files (`theme.html.php`, `header.php`,
  `footer.php`) stay PHP.
  - **No `include __DIR__` any more:** a compiled template lives in the cache, where
    `__DIR__` points elsewhere. The three views that used it now use `@include`: `ai/ask`
    includes `../chat/chat`, tailwind's `profile` includes `../partials/account_sidebar`, and
    `services` includes its refresh script.
  - **The refresh script was renamed:** `services/refresh.php` is now `services/refresh.tpl.php`.
  - **How each is checked:** every converted view is drawn before and after with the same
    variables, and kept only when the two outputs are the same.
  - **Overrides are kept:** an application that overrides one of these views with its own
    `.html.php` keeps its override, because the application's file is found before the
    scaffold's of either kind.

### Fixed

- **The conversation page's connection token field has an id and a show/hide toggle**, like
  every other password field. The check that requires both never saw this field: the PHP inside
  its `class` attribute cut the tag short.
- **`switch-ui` names a published view in either kind.** A view copied with
  `project:publish-views` as `.html.php` is still recognised once the bundled view is a
  `.tpl.php`.

## A template directive's condition at any depth

### Fixed

- **`@if`, `@foreach`, `@include` and the other directives with an argument cut a deeply nested
  argument short.**
  - **What happened:** the compiler matched the parentheses with a regex that reached only three
    levels. A condition with a closure in it, such as
    `@if (count(array_filter($rows, fn ($r) => $r['status'] === 'Unpaid')) > 1)`, compiled to
    PHP that did not parse.
  - **The fix:** the argument is now matched at any depth, and parentheses inside quoted strings
    are ignored.

## Generated views are templates by default: `create:crud`, `create:view`, `init`

### Changed

- **The views generated into an application are `.tpl.php` templates** in the framework's
  template engine, unless `.html.php` is asked for.
  - **`create:crud` and `create:view --full`** write the list, edit and show views as templates.
  - **`create:view`** without `--full` writes its placeholder from a new template stub. It also
    takes `--views` now.
  - **`init`** writes the home page as `src/Views/home/home.tpl.php`.
- **To keep `.html.php`:** pass `--views=html` to `create:crud` or `create:view`, or set
  `'make' => ['views' => 'html']` in app.php for the whole project. Views that already exist
  are not touched, and a controller draws either kind without a change.

## A remembered sign-in survives two requests at once

### Fixed

- **A second request sent alongside the first, with the same `auth` cookie, is no longer signed
  out.** `Auth::rememberLogin()` deleted the token as soon as it used it. A browser that sends two
  requests at once, such as a mail app that opens a link twice within a second, had its second
  request arrive with a token that was already gone, and that request landed on the sign-in page.
  - **What changed:** the replaced token is now retired (`RememberTokens::retire()`). It keeps
    signing in for `RememberTokens::GRACE` (60) seconds and then expires. Each use within that
    time issues a token of its own.
  - **Setting:** `'auth' => ['remember_grace' => …]` in app.php sets the grace, in seconds.
  - **What stays immediate:** signing out (`revoke()`) and signing out everywhere end tokens at
    once, with no grace.

### Documentation

- [Authentication guide](../../Pramnos_Authentication_Guide.md).

## An error in a template names the template and its line

### Fixed

- **An error inside a `.tpl.php` template points at the template**, not at the compiled file in
  the cache, whose name is a hash (`var/viewcache/3f9a….php`).
  - **Where it shows:** the error page in debug mode, the trace written to the log, the `file`
    of a JSON error, and the debug bar.
  - **How:** the compiled file's first line records the template it came from
    (`TemplateCache::sourceOf()`), and these read it back.
- **The line is the template's own.** `{{-- … --}}` comments now keep their line breaks when
  they are stripped. Every line of the compiled PHP is therefore the same line of the template.
  A comment of several lines used to shift every line below it.
- **The view's *"Error rendering template file … at line N"* gives the template's line.** It used
  to give the line where the exception was thrown, which is often inside a class the template
  called. It now also carries the original exception as its previous one, so its trace is not
  lost.
- **Templates compiled before this change** keep pointing at the cache until they are compiled
  again. A template is compiled again when it changes, or when `var/viewcache/` is emptied.

### Documentation

- [Framework guide](../../Pramnos_Framework_Guide.md), templates in the template engine.

## Upload file types per module, from app.php

### Added

- **`'media' => ['extensions' => ['<module>' => [...], '*' => [...]]]`** in app.php adds file
  types that `MediaObject::uploadFile()` takes for a module, beside its own list (pictures, `pdf`,
  `xls`, `xlsx`). Before this, the list was fixed in code: a module that takes log files or
  archives, such as a ticket's attachments, could not use `MediaObject`.
  - **Scope:** the extra types apply only to uploads that are not pictures, are stored as
    documents (media type 0), and their `Content-Type` is not checked against a list.
  - **Never allowed:** `MediaObject::NEVER_EXTENSIONS` (`php`, `html`, `js`, `htaccess`, `exe`
    and others) are refused even when listed.
  - **Hook:** `moduleExtensions($module)` can be overridden instead, like
    `privateStorageModules()`.

### Documentation

- [Media guide](../../Pramnos_Media_Guide.md), which file types a module takes.

## Help is searched and read by section

### Changed

- **The help search counts sections, not pages.** Each `##` of a page is searched on its own, a
  long one by its `###` parts, with its path («Page › Section») counting as a title. Sections are
  scored by BM25, which holds a long section back for its length. Before this, a page of 18,000
  characters won nearly every question for being long. `Help::search()` still returns pages,
  each scored by its best section, which comes with it as `best`.
- **The analyst's `help` tool answers with a section.** It gives the best section whole, with a
  link to its heading, and the next three by path. Before this it gave the first 6,000 characters
  of the best page, so a section further down a long page never reached the model. It now also
  reads `page` + `section`, gives a page's sections for `page` alone, lists every page and section
  for `map`, and keeps one group for `topic`.
- **Help pages' headings have ids**, the anchors those links end with.
- **A page's own `questions:` bring its answering section, not its opening.** They lift the page,
  and the lift goes to the page's best section by its own words. Given to the opening, a match
  answered with one or two sentences and the assistant had to ask again.
- **Changelog posts count half against guides** (`source: changelog`), unless the question asks
  what changed or when.

### Added

- **Questions per section:** a `<!-- questions: … | … -->` line under a heading.
- **Synonyms:** `_synonyms.php` in a help directory. A question's word brings its group in at half
  weight.
- **`help:eval`:** recall@1 and recall@3 of the search against the golden questions in a help
  directory's `_golden.php` (question → `page` or `page#anchor`). `--min` exits 1 below a recall@3.
- **API:** `HelpBook::sections()`, `section()`, `searchSections()`, `map()` and `synonyms()`;
  `Help::sections()`, `anchor()` and `anchors()`.

### Documentation

- [Administration help guide](../../Pramnos_Admin_Assistant_Guide.md), Search.

## `help:questions`: a model proposes the questions a help section answers

### Added

- **`php bin/pramnos help:questions`** goes through the help sections that have no questions and
  asks the configured connection's cheapest model for two to four questions each answers, in the
  page's language. It prints them, and `--write` puts them under each heading as
  `<!-- questions: … -->` for the author to correct.
  - **Why:** a section's own questions are what lifts the help search the most. In one
    installation they took the answer coming first from 0.47 to 0.88 of real questions, and they
    are the tedious part to write.
  - **What it leaves alone:** a section that has questions, and the framework's own pages unless
    `--framework`.

### Documentation

- [Administration help guide](../../Pramnos_Admin_Assistant_Guide.md), Search, and the
  [Console guide](../../Pramnos_Console_Guide.md).

## A help page no longer shows its questions to the reader; the framework's pages have them

### Fixed

- **A section's `<!-- questions: … -->` line was shown on the help page** as text, on the help
  screen, in the side panel and in the help API, since the Markdown renderer escapes HTML.
  `Help::html()` now leaves out every line that is only an HTML comment. A comment inside a line
  of text stays text.

### Documentation

- **The framework's own help pages have questions per section**: 74 sections of its 23 pages, for
  the administration screens an application gets. They were written through `help:questions`.

## `help:gaps`: where the help fell short of what the analyst was asked

### Added

- **`php bin/pramnos help:gaps`** reads the analyst's conversations. Every answer keeps the tools
  it called (`chat_messages.tools`), so each `help` call is stored with its answer and that
  answer's rating. It answers each question again with the help as it is now, and lists, most
  asked first:
  - the questions nothing answers;
  - those answered below `--weak`;
  - the sections read by name after a search did not bring them.
- **`--rated=bad`:** for each answer rated bad, the help behind it with the answer's note. It says
  whether the help has nothing strong for it, or had a strong section the answer did not use.
- **`--golden`:** prints every question as a `_golden.php` line with the answer it gets.
- **On the conversation screen:** each `help` call shows the section the help gives and its score.
- **No log file.** A first version earlier today wrote each search to a `help` log file instead.
  It was replaced the same day: a file did not know the conversation or the rating, was not shown
  in the administration, and held the administrators' questions outside the conversations'
  permissions and retention. `HelpTool::lookedUp()` reads a stored call back.

### Documentation

- [Administration help guide](../../Pramnos_Admin_Assistant_Guide.md), Search, and the
  [Console guide](../../Pramnos_Console_Guide.md).

## Email confirmation that does not hold the account back, and an administrator's resend

### Added

- **`EmailVerification::request($userId)`** mails the confirmation link and marks the account
  `validated = 0` without holding it back at sign-in. `begin()` holds it back. Following the link
  sets `validated = 1` as before.
- **`awaitsConfirmation($userId)`** says whether a link is out and not followed, for an
  application's "confirm your email" notice.
- **`resend($userId)`** mails a fresh link at once to an unconfirmed account, held back or not.
- **Resend verification email**, on a user's page in the administration, for an unconfirmed
  account with an address. It is recorded in the account's activity.

### Documentation

- [Auth and users guide](../../Pramnos_Auth_Users_Guide.md), confirming the address; the Users
  help page.

## Several attachments on one email, by file or bytes, queued too

### Added

- **`Email::addAttachment($path, $name, $mime)`** attaches any number of files, each shown to the
  recipient under the name given. A file kept as `123456_invoice.pdf` arrives as `invoice.pdf`.
- **`Email::addAttachmentData($bytes, $name, $mime)`** attaches bytes made in memory, without a
  temporary file of the caller's.
- **Queued as well:** the attachments survive `queue()`. Bytes wait in a file under
  `var/mail-attachments/` rather than in the outbox row, whose column holds 64 KB on MySQL, and the
  worker deletes that file once the message is sent or given up.
- **`attachments()`** lists them. `$email->attach` still takes its one file, as before.

### Documentation

- [Email guide](../../Pramnos_Email_Guide.md), Email with attachments.

## The picture crop dialog's tools work when the click lands on their icon

### Fixed

- **Rotate, flip and reset in `pf-image.js`'s crop dialog did nothing when the click landed on
  the button's icon**, which is where a click on a tool usually lands. The handler read the action
  from the clicked element alone, the icon's `<path>`, which has none. It now reads it from the
  button the click is inside (`closest('[data-pf-image-action]')`). Cancel and Use worked all
  along, having no icon.
- **For applications:** a copy of `pf-image.js` in `www/` is refreshed by `project:resync`.
