## `Document`'s default scripts and stylesheets are now versioned with `mtime`, not an empty string (FW-578)

### Fixed

Every script and stylesheet `Document::__construct()` pre-registers — `jquery`, `jquery-ui`, the
`datatables` family, `jquery-fileupload`, `bootstrap-datepicker`, `jquery-inputmask`, the restored
`slimbox2`/`thickbox`/`spectrum`/`Spry*` handles and their stylesheets — was registered with `''`
as its version, even though `registerScript()`/`registerStyle()` have supported `'mtime'` for a
while: it stamps the URL with the file's own modification time through
`Document::stamped()`/`assetUrl()`, so a deploy becomes a new address instead of the same one.

An unversioned URL never changes, so a cache sitting in front of the application can only ever
treat it as a short-lived response, because the same address might serve a different file
tomorrow — reported against a reverse proxy's default browser-cache TTL. These are
framework-owned registrations an application cannot repoint without re-registering the handle
itself, so every application on this framework carried the same gap.

All of them now register with `'mtime'`, same as any application's own assets following the
guide's example. The two `jquery-inputmask-extensions`/`-date` alias handles are untouched — they
register with no `src` at all (nothing to resolve to the 3.3.4 bundle they alias), so there is
nothing to stamp a modification time from. The three CDN-hosted handles (`jquery`,
`bootstrap-datepicker`, `jquery-inputmask`) also keep `'mtime'`: `stamped()` leaves a remote URL
alone, so it costs nothing there.
