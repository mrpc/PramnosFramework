# 2 October 2026

3 changes:

- Two workers refreshing one OAuth connection no longer kill it
- A faked request says its method, URL, headers and body
- `QueueManager::addMany()` queues a pass as one batch

## Two workers refreshing one OAuth connection no longer kill it

`ConnectionStore::refresh()` took no lock, and did not read the row again before using it.
Two workers reading channels on the same sign-in both refreshed the token. A provider that
rotates refresh tokens (TikTok) accepted the first and answered the second `invalid_grant`.
`refresh()` treats that as terminal, so the connection was marked dead and the user had to
authorise again for something they had not done.

### Fixed

- **`refresh()` takes a `SharedLock` on the connection** (`oauth:refresh:<id>`, across
  servers) and reads the row again once it holds it. Tokens another process has just
  refreshed are returned without a request. A connection that died or was forgotten in the
  meantime raises a terminal error without contacting the provider.
- **A caller that waits 30 seconds without the lock** gets a non-terminal
  `OAuthClientException` with `error = 'temporarily_unavailable'`, and the connection is
  left alone.

A behaviour change; see the *`ConnectionStore::refresh()`* row in the
[Upgrade Guide](../../Pramnos_Upgrade_Guide.md#since-v12-unreleased).

### Documentation

- [OAuth Client Guide — Refreshing from several workers at once](../../Pramnos_OAuth_Client_Guide.md#refreshing-from-several-workers-at-once).

## A faked request says its method, URL, headers and body

A callable fake receives the `Client`, but its method, URL, headers and body were private,
so a test that a call went as PATCH and was signed `Bot <token>` read them through
reflection. The URL pattern a fake is registered under cannot tell a POST from a PATCH.

### Added

- **`method()`, `url()`, `requestHeaders()` and `requestBody()`** on `Pramnos\Http\Client`.
  `requestHeaders()` is named so as not to clash with the `headers()` setter.

### Fixed

- **A `Content-Type` or `User-Agent` set with `header()` is sent once.** The transport now
  builds its header list from `requestHeaders()`, where a hand-set header replaces the
  automatic one of the same name. Before, both went out.

See [HTTP Client Guide — Testing without the network](../../Pramnos_Http_Client_Guide.md#testing-without-the-network).

## `QueueManager::addMany()` queues a pass as one batch

A scheduled pass ("for each due channel, collect it") could only reach the worker pool through
an enqueue-per-item loop each application wrote itself, around an `addTask(unique: true)`
that checked for a duplicate and then inserted, so two producers could both insert.

### Added

- **`QueueManager::addMany($taskType, $payloads, priority:, maxAttempts:, unique:, batch:)`**
  queues one task per payload in one transaction and returns a `QueueBatch`: `id`, `name`,
  `taskIds`, `skipped` and `queued()`.
- **`unique` is atomic.** It runs under a `SharedLock` on the task type and counts a
  duplicate only while it is `pending` or `processing`.
- **`queueitems.batchid` and `batchname`**, indexed with `status`, by a new `queue`
  migration.
- **`SharedLock::acquireWithin($seconds)`**, which waits for a lock instead of giving up at
  once. `ConnectionStore::refresh()` now uses it too.

See [Queue Guide — Spreading a pass over the worker pool](../../Pramnos_Queue_Guide.md#spreading-a-pass-over-the-worker-pool-addmany).
