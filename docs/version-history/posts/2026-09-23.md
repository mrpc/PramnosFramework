## A migration that adds a column left the model's column list an hour stale

`getColumns()` caches a table's schema for an hour. `SchemaBuilder` invalidates the tables
its own DDL methods touch, so a migration written against the builder is covered — but
**DDL is explicitly allowed to be raw**, because the builder cannot express every engine's
grammar, and a raw statement flushed nothing.

`ALTER TABLE channels ADD COLUMN is_competitor …` therefore left
`schema_columns_channels` holding the old list. Every list built through `getApiList()`
kept answering without that key; the payload indexed it by name, so an undefined-key
warning printed **ahead of the body**, the JSON would not parse, and the screen read
"Could not load your numbers" — with no status, because nothing had refused anything.

The read path's own comment called this *"visible, harmless, and fixed by waiting"*. It is
harmless to a reader that walks the row. Every generated controller and every hand-written
payload indexes it by name, and "harmless" is what stopped anybody thinking about it.

### Fixed

- `MigrationRunner::run()` calls `Database::forgetAllColumns()` when a batch ran anything.
  **Every table, not a list of what changed**: the runner cannot know which tables a raw
  statement touched without parsing SQL, and a list that is nearly right is worse than
  none — the table it misses is the one the migration was about. A `migrate` that finds
  nothing pending flushes nothing, which is the common case on every deploy.
- Both cache keys per table. `getColumns()` caches under whatever string it was handed, so
  `#PREFIX#channels` and `pramnos_channels` are two entries for one table and the
  catalogue only knows the second — flushing one of them is a flush that reports success
  and leaves the stale answer in place.
- The comment says what it costs now.

### Added

- `SchemaBuilder::tableNames()`, pinned to the connected database because
  `information_schema` spans every database on the server, and aliasing `table_name`
  because MySQL answers it in upper case.
- `ColumnCacheAfterMigrateTest`, which drives a raw-SQL migration through the runner. It
  asserts first that the cache **is** caching — a disabled cache would make every other
  assertion pass on a runner that does nothing — and that an empty batch does *not* flush.

  Writing it turned up its own version of the bug: the cache outlives a test, so two tests
  sharing a table name share an entry and the second reads what the first left. Each test
  has a table of its own now.


## There was no supported way to post a form in a test

`TestClient::submitForm()` threw `submitForm is not yet fully implemented` while the class
documented it as the way to post a form. So a test that wanted to exercise registration, a
password reset or a settings form built the POST by hand — and the hard part is the CSRF
token, whose field **name** is a private property and whose **value** is
`getFingerprint()`, also not public.

The only way in was a regular expression over `getTokenField()`'s markup, in every
application that tests a form. Those are the highest-value tests in an application with
accounts in it, and the ones most likely to be skipped, because the first hour of writing
one went on this rather than on the behaviour.

### Added

- `Session::tokenParameters()` — three lines, returning `[field name => fingerprint]`, the
  same two strings the hidden input carries. `tokenParameters(true)` for the IP-pinned
  variant, matching `getTokenField(true)`.
- `TestClient::submitForm()`, implemented. It reads the form off the page the client last
  received: the action, the method, and every field already rendered, the hidden CSRF
  input included. `$data` overrides by name, so a settings form with thirty fields and one
  under test submits the other twenty-nine as the page had them.

  The client keeps the last response for it — recorded in `call()` rather than at each
  `return`, because the dispatch has five of them and a client that remembers four pages
  out of five is worse than one that remembers none.

- Tests for both. `tokenParameters()` is asserted **against `getTokenField()`** rather
  than against a literal, because the contract is that the two agree: a test naming the
  field itself would pass while they drifted, which is the only way this can go wrong.
