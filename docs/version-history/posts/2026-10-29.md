Two entries today:

- What somebody else wrote reaches the model as data, and holds back writes

## What somebody else wrote reaches the model as data, and holds back writes

### Added

- A tool marked `'untrusted' => true` is one that reads words somebody else wrote, such as an
  email, a customer's message or a document from outside. Its result now reaches the model
  between `UNTRUSTED DATA <token>` and `END UNTRUSTED DATA <token>` lines. The token is random
  for each call, so the text cannot close the boundary. The system prompt says, in
  `Client::DATA_NOTICE`, that nothing inside is an instruction.
- Once such a result has been read in an answer, a tool marked `'writes' => true` is not run for
  the rest of that answer. The model is told why (`Client::HELD_WRITE`) and asks the person to
  confirm. A conversation marks its assistant's `writes()` itself, which includes `remember`,
  `forget` and the scheduling tools.
- A conversation with an attached document gets the same notice in its system prompt.

### Fixed

- Memory learning read the whole user message, an attached document included, so words from an
  attached email could be learned as the person's own. It now reads only what the person typed.

## The context is budgeted in tokens, not messages

### Added

- Within one answer: past 70% of the connection's `context_window` (`Client::ROOM`), the tool
  results of that answer before the last two are replaced with a note naming their tool
  (`Client::SET_ASIDE`, `Client::makeRoom()`). An answer that reads a lot no longer runs into the
  window.
- Between answers: a conversation is folded into its summary when the last answer left the window
  more than 60% full (`Conversations::FULL`), not only once it has many messages. A few long
  messages fill the window as surely as many short ones.
