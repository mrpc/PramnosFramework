## What somebody else wrote reaches the model as data, and holds back writes

### Added

- A tool marked `'untrusted' => true` is one that reads words somebody else wrote, such as an
  email, a customer's message or a document from outside. Its result now reaches the model
  between `UNTRUSTED DATA <token>` and `END UNTRUSTED DATA <token>` lines. The token is random
  for each call, so the text cannot close the boundary. The system prompt says, in
  `Client::DATA_NOTICE`, that nothing inside is an instruction.
- Once such a result has been read in an answer, a tool marked `'writes' => true` is not run for
  the rest of that answer. The model is told why (`Client::HELD_WRITE`) and asks the person to
  confirm. A conversation marks its assistant's `writes()` itself, which includes `remember`,
  `forget` and the scheduling tools.
- A conversation with an attached document gets the same notice in its system prompt.

### Fixed

- Memory learning read the whole user message, an attached document included, so words from an
  attached email could be learned as the person's own. It now reads only what the person typed.

### Documentation

- [LLM guide — tools](../../Pramnos_LLM_Guide.md#what-somebody-else-wrote-is-data-not-instructions).

## The context is budgeted in tokens, not messages

### Added

- Within one answer: past 70% of the connection's `context_window` (`Client::ROOM`), the tool
  results of that answer before the last two are replaced with a note naming their tool
  (`Client::SET_ASIDE`, `Client::makeRoom()`). An answer that reads a lot no longer runs into the
  window.
- Between answers: a conversation is folded into its summary when the last answer left the window
  more than 60% full (`Conversations::FULL`), not only once it has many messages. A few long
  messages fill the window as surely as many short ones.

### Documentation

- [LLM guide — tools](../../Pramnos_LLM_Guide.md#tools) and
  [conversations](../../Pramnos_LLM_Guide.md#conversations).

## A busy provider is asked again, and a failing one can fall back to another

### Added

- A request answered with a timeout, 429, 5xx, 529 or no answer at all is asked again after 2 and
  then 5 seconds (`Client::RETRIES`, `Client::PASSING`). A 400 is not.
- `'llm' => ['fallback' => 'mistral']`: still failing, the answer goes to that provider, but only
  where it may take it. It needs a key, agreement where agreement is asked for, room within the
  limits, and every data tag the answer read or its conversation holds accepting it. The payload
  is rebuilt for that provider.

### Documentation

- [LLM guide — when a provider is busy or down](../../Pramnos_LLM_Guide.md#when-a-provider-is-busy-or-down).

## An answer shows while it is written

### Added

- `Client::onText(callable)` is told the answer's text so far while the model writes it.
  `OpenAiCompatible::chatStream()` reads the provider's server-sent events and puts the tool calls
  and usage back together, so the answer returned is the same as without streaming. A provider
  that refuses the streamed request (400, 422) is asked again the ordinary way. A transport
  without `chatStream()` answers as before.
- A question asked in the background is streamed by the worker into the new
  `chat_asks.partial` column (migration `2026_10_29_000001`), at most every half second. The
  column is emptied once the question is answered. `Asks::find()` and the `asked` endpoints return
  it as `partial`. `pf-chat.js` and the SPA's `waitForAnswer()` (new `onpartial`, `partialMs`)
  show it as it grows, and look at the ask every 700 ms while it does. Without the migration,
  nothing changes.
- `Http\Client::onChunk(callable)` is told each piece of a 2xx body as it arrives.

## The Ask page is the application's own: a greeting, one composer, `/` commands

### Added

- An empty conversation on `/chat` and on the analyst's page is now a greeting over one large,
  rounded composer, with the example questions under it. An open conversation keeps the
  composer at the bottom of the view, and the composer grows with what is written.
- `/` at the start of the composer opens a menu of commands: `/new`, `/scheduled`, `/attach`,
  `/memory`, then the application's own. The menu works from the keyboard and follows the ARIA
  combobox pattern.
- New branding keys in `'llm' => ['chat' => …]` (and `'analyst'`): `greeting`, `placeholder`,
  `accent` and `commands`. `Chat\Web\ChatLook` checks the accent and builds the command list.
- The SPA's `Chat.svelte` has the same layout: a greeting over the composer, the examples under
  it, and a `/` menu that works from the keyboard. New props: `greeting`, `avatar`, `accent`,
  `commands`. Existing projects pick it up with `project:resync --spa-components`.
- The styles are a new *Ask* section in each theme's `components.css`. They set shape and layout
  on the shared tokens, so Bootstrap, daisyUI and the plain theme each keep their own buttons and
  colours.

### Fixed

- 👍, 👎 and the note sit on one line in every theme, in that order. A theme's input is a
  full-width block, which had put each of them on its own line, and the note now comes after 👎
  (`RatingView`). Between the two buttons it looked as if it belonged to either. The emoji are
  larger, and the pressed one is marked.
- Three test classes depended on the order they ran in. The chat page's and the users screen's
  tests now create `userdetails` themselves, because loading an account reads it beside `users`.
  The groups screen's tests forget what `Groups` remembered about the previous class's database.

## A guest is sent to the application's own sign-in; the analyst's picture keeps its size without the theme

### Added

- `'auth' => ['login_url' => 'account/login']` names where a guest signs in, and
  `SecurityPolicy::loginUrl($return)` builds the address.

### Fixed

- 👍 and 👎 keep their look under a theme whose link-button hover underlines and fills them
  (`.btn.btn-link:hover`), with a visible focus ring of their own.
- The Ask page's new words are in Greek.
- An empty Ask page introduces the assistant by name only where the application named it
  (`ChatLook::greeting()`). The framework's own "Ask" made it say "Hi, I am Ask". The page's ⚙ sits
  in the conversation column's top corner, placed by `components.css` instead of inline styles
  that an application had to override with `!important`.
- The scheduled page's breadcrumbs reach the open task: the conversations, Scheduled, and the
  task's title (`SchedulesTasks::scheduledCrumbs()`, `taskChatName()`). The trail used to end a
  level short.
- The analyst's conversations and artifacts are shared only with people at or above its floor.
  The notification had told somebody below it that a conversation existed, and its title, and
  led to a page that refused them.
- The Ask page is one column 1100px wide (`--pf-chat-width`): the title, Share and the answers'
  tools line up with the conversation, which was an 820px strip with the title at the far left.
- On the Ask page, 👎's note ("What was wrong?") shows on the first press of 👎 rather than
  sitting beside the buttons from the start, and the next press sends it. Without JavaScript it
  is on view as before.
- The analyst's picture (`AvatarSets::render()`) carries its size inline, through
  `--pf-assistant-size`, and the framework's drop carries its colours as SVG attributes. On a
  page whose theme does not load `components.css`, it was drawn as a black shape the width of the
  page.
- Every place that sent a guest to sign in pointed at the site's `login`, which an application
  whose sign-in is elsewhere does not have. That covered a protected action, a screen behind a
  usertype floor (including a report's link opened from an email), an administration area without
  its own sign-in, and the Ask, messages, passkey, second-factor and OAuth pages. All of them now
  ask `SecurityPolicy::loginUrl()`, so the guest lands on the configured page and no longer on a
  404.

## Names are suggested as they are typed, when sharing and choosing a report's readers

### Added

- In the analyst's space, the *With* field of a share and a report's readers field suggest
  people for the name after the last comma. The suggestions are asked from the API as the name is
  typed: `GET /chat/people?q=` (the `people` action on the pages), answered by
  `SharePolicy::candidates($scope, $term)`, which returns active accounts at or above the
  analyst's floor matched by username, email or name, ten at most. `pf-utils.js` (`data-pf-people`)
  waits for two characters and a 300 ms pause, cancels the request before when a new one leaves,
  keeps each answer, and shows one only while the field still says its term. A person's own Ask
  suggests nobody.

## A breadcrumb without a label raises no deprecation on PHP 8.5

### Fixed

- `Html\Breadcrumb::addItem()` with a null label, for example from a page with no title, used the
  null as an array key. PHP 8.5 deprecates that, and an application whose suite turns
  deprecations into failures stopped on it. The label is now the empty string, which is what the
  key always became.

## Late writes on TimescaleDB 2.31: one value directly, an import per chunk, within a WAL budget

### Added

- On TimescaleDB 2.31 and later, `DeferredWriteQueue::write()` writes one late value into its
  compressed chunk directly instead of queuing it. Past `BULK_AFTER` (1,000) late rows in one
  process, or after `bulk()`, rows are queued for the drain as before.
- The drain decides per compressed chunk. It writes directly and compresses once at the end,
  unless the pending rows reach half the chunk or the corrections among them reach 15%, in which
  case it rewrites the chunk. Corrections are estimated by sampling the declared conflict key.
  Direct batches lift TimescaleDB's limit on rows decompressed per transaction.
- `timescale:drain` stops before the next chunk once it has written `--wal-budget` MB of WAL
  (default 20 GB), or while a streaming replica is `--replica-lag` MB behind (default 10 GB), and
  says so. The rest waits for the next run.
- The figures behind the thresholds were measured on TimescaleDB 2.31.0 with PostgreSQL 18, on a
  554 MB chunk. A rewrite cost 1.3–1.8 GB of WAL whatever the number of rows. Direct writes cost
  20–40 kB for one row and 0.45 GB for a million. Corrections spread over every device broke even
  near 15% of the chunk.

- [Hypertable guide — writing late data into a compressed table](../../Pramnos_Hypertable_Guide.md#writing-late-data-into-a-compressed-table),

## After a lost connection, reads and writes stay one session

### Fixed

- Without a read/write split, reads and writes share one connection. After that connection was
  lost, each role reconnected on its own: the write for the next INSERT, the read for the next
  SELECT. From then on they were two sessions for the rest of the process. A long-running worker
  then read outside its own transactions, and on PostgreSQL `getInsertId()`'s `currval()` ran in a
  session that never used the sequence. A scheduler running when PostgreSQL restarted failed its
  run log with «currval of sequence "scheduleruns_id_seq" is not yet defined in this session».
  `getConnection()` now reconnects the one connection for both roles.
- With a split, `getInsertId()` asked the read replica for `currval()`, where it always fails. It
  now asks on the write link, where the INSERT ran. A failure there raises as any failed
  statement does, and the id is still an integer.

## The DevPanel's database tab reads `pg_stat_statements`: queries per second, per role, top statements, connected applications

### Added

- The *Slowest statements* section of `/devpanel/db` is now **Statements**. It shows calls,
  execution time, WAL and calls per second since the counters' last reset, broken down by
  database and role. It also lists the top 25 statements with calls, total and mean time,
  rows, cache hit ratio and WAL bytes, and the list can be sorted by any of those columns. A
  live table shows connections per `application_name`. A **Reset statistics** button calls
  `pg_stat_statements_reset()` after a confirmation and a CSRF check.
- The section says which of three things is missing: the library in
  `shared_preload_libraries`, the extension in the database, or `pg_read_all_stats` for the
  role. Without that role, other roles' statement text is hidden, and the page now says so.
- `DatabaseInspector::getStatementStats($sort, $limit)` and
  `DatabaseInspector::resetStatementStats()`. `getSlowStatements()` is unchanged.

### Fixed

- The **Kill** button on the database tab asked for confirmation in its markup, but no script
  on that tab read it, so it ended the backend without asking. It now asks, as does the reset.
