## `LogViewer` escaped a log entry's `timestamp` field, and `renderError()` escapes its own message

### Fixed

- `renderLines()` ran every field of a decoded log entry through `htmlspecialchars()` before
  rendering it except `timestamp`, which went straight into the page. `renderError()` now
  escapes its own `$message` instead of relying on every caller to have done it already.

## `Database::replicaConnection()` -- a read-only connection to a replica, for one caller, without the global read/write split

### Added

- `Database::replicaConnection(?string $hostname = null, ?int $port = null): self` -- a second,
  independently-connected `Database` instance pointed at a replica, reusing this instance's
  user/password/database/type so nothing is re-entered. Any write statement on it throws a
  `RuntimeException` instead of running. Omit the hostname to fall back to the `read` config
  block's own hostname/port, if one is configured.
- Addresses a real production incident: a heavy read-only batch job needed the already-live
  replica without turning on the application-wide `read`/`write` split, which would have sent
  every `SELECT` everywhere to the replica -- a real stale-read risk for unrelated
  save-then-immediate-read code paths.

## The Tailwind theme's "Show X rows" `<select>` was clipped and its open popup had no background

### Fixed

- `.pf-datatable .dataTables_length select` set `width: auto`, which daisyUI 5.7.22's new
  `appearance: base-select` rendering mode sizes to the selected value alone ("10"), not to the
  widest option or the dropdown arrow the theme draws in its background — the digits sat on top
  of the arrow at roughly 26px wide. The rule now sets `min-width: 4.5rem`.
- The same `<select>`'s open popup rendered with no background at all — transparent, floating
  unreadably over the table underneath. `appearance: base-select` opts a `<select>` into Chrome's
  experimental Customizable Select API so the page can style `::picker(select)`, but the theme
  does not style it, and the build this was found on shipped that popup with no background in the
  experimental mode. `appearance: menulist` on the same selector opts this one `<select>` back
  into the plain native popup, which has a background in every browser.
