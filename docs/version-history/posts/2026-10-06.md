## The suite's speed is back: 394 s of tests down to 303

Making the suite independent of test order cost 92 seconds of test time. The sequential run
went from 5:22 to 6:59. Comparing the time of every class between the two versions put
nearly all of it in classes that build their tables with `Testing\Schema::table()` from
`setUp()`. `AdminAccessTest` went from 2.3 s to 11.3 s.

### Fixed

- **`Testing\Schema::table()` builds a table once per process.** It ran every migration in
  the recipe on every call, and each migration asked the catalogue whether its table and
  columns exist. `usertokens` now also builds `users` and `applications` first, which made a
  call about 280 ms on MySQL. The first call now records the table's columns, and later
  calls compare them in one query, rebuilding only a table that was dropped or reshaped.
- **`AccountChangePasswordTest`** removes any row for the process's own session before it
  records it. The session id belongs to the process, so under `--parallel` an earlier class
  in the same worker could have recorded the same session for another user.

Measured on databases dropped before each run: 303 s of tests and 5:24 wall time
sequentially, against 302 s and 5:22 before the isolation work. The parallel run takes
1:33 for the workers and 0:44 for the serial group.

## The OIDC `phone_number` claim falls back to the phone when there is no mobile

`UserClaims` filled `phone_number` with `$u['mobile'] ?? $u['phone']`. In the shipped
schema both columns default to `''`, not `null`, so for a user with no mobile the claim was
always `''`, even when a phone number was on file. It is now the mobile, else the phone,
else `null`, which is how OIDC says a claim has no value.

The test that should have caught this had made `users.mobile` nullable with an
`ALTER TABLE` and then set it to `NULL`. That was a shape no installation has.

### Fixed

- `phone_number` uses `phone` when `mobile` is empty, and is `null` when both are empty.
- `OauthCoverageTest` no longer patches the framework tables after building them from their
  migrations. Its `ALTER TABLE` block dated from hand-built copies, and it reshaped the real
  tables: `users.mobile` nullable, `maingroup` added. The one test that reads `maingroup`,
  which is an application's column and not the framework's, adds it for its own duration.

### Documentation

- Upgrade Guide: a row for clients that read `phone_number` and treat `''` as "no number".
- AuthServer Integration Guide: where `phone_number` comes from.
