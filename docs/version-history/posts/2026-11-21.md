## A figures correction's round budget grows with the chain it actually takes (FW-572)

### Fixed

After a figures correction (`Client::FIGURES`), the retry's round budget was a flat `$round + 2`
— enough for one tool call and the answer, whatever the actual chain to a correct number needed.
Reported live from exactly that: the retry correctly read a `schema` tool first, but had no round
left to call `sql` with what it learned, and was forced to answer with nothing new to show for it.

Now each round after the correction that still genuinely calls a tool earns one more: the chain
gets as many rounds as it actually takes, not a ceiling fixed the moment the correction fired. The
existing over-budget check still stops it growing forever once the answer's cost or token budget
is spent.

### Documentation

`docs/Pramnos_LLM_Tools_Guide.md`'s figures section now describes the grown-as-needed round
budget.
