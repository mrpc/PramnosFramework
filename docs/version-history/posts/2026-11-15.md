## `pf-voice.js`: server dictation calls `onSilence` before `onEnd`, like the browser's own (FW-503)

With the browser's own speech recognition, a silence stops dictation and calls `onSilence`
synchronously; the recognition's own `onend` — which calls `onEnd` — arrives later, asynchronously.
A caller that follows the ordinary pattern, `onEnd: () => { if (listening) endConversation(); }`,
relies on that order: `onSilence` has already cleared `listening` by the time `onEnd` runs.

Dictation by a server (`createVoiceState({ listen: fn })`, FW-437 — Firefox, an installed app on
an iPhone) called them the other way round: `onEnd` fired as soon as the transcription promise
resolved, before `onSilence`. A caller using the same pattern read `listening` still `true` and
ended the conversation it had just restarted — invisible until server-based dictation started
working end to end, when the microphone that should have reopened never did.

### Fixed

- `serverDictation()`'s `finishServer()` now calls `opts.onSilence()` before `ended()` (which
  calls `opts.onEnd()`), matching the order the browser's own recognition path already used.

### Documentation

- `Pramnos_LLM_Analyst_Guide.md`, "Voice": the ordering made explicit, with why it matters for a
  caller's own `onEnd`.

## A client-side wrapper can tell the model its own device state, for one question (FW-504)

A desktop wrapper (Electron, a native shell) can know things the server never does — a model
downloading, a script it is running on the person's own word — kept entirely in its own IPC
today. Asked "what are you doing right now?", the model had no way to know, and no hook existed
to tell it without inventing a new field of the conversation's own history.

### Added

- `extra['local']` — a short string an application's own `TakesQuestions::extra()` override adds
  from whatever its own channel carries, told in zone 3 (`ContextAssembler::dynamicTail()`) for
  that question alone: `Happening on the person's own device right now, not said by them: …`, cut
  at `ContextAssembler::MAX_LOCAL` (200 characters). Like the time and the page, never part of the
  conversation's own history, and the model is told plainly it is not something the person said.

### Documentation

- `Pramnos_LLM_Conversations_Guide.md`, "The context, in three zones": `extra['local']` added.

## `json_query`: a table artifact's rows, filtered and projected, without reading it whole (FW-505)

`read_artifact` cuts a long artifact at a fixed number of characters — fine for a document, not
for a table of hundreds of rows the model is asked a specific question about ("which orders are
still open?"), where the cut lands mid-row and the one row that mattered may already be past it.

### Added

- `json_query` (`Artifacts::workspaceTools()`, the `artifacts` skill): a table artifact's rows,
  `where` (column => value, exact match, case-insensitive; every pair given must match) and
  `select` (which columns to keep). `limit` caps how many rows, 50 by default, 500 at most.
  Refused for a kind that is not a table — a list or a chart is short enough for `read_artifact`
  to read whole — and for one that is not this person's own or shared with them, like every other
  artifact tool.

### Documentation

- `Pramnos_LLM_Conversations_Guide.md`, "A workspace across conversations": `json_query` added to
  the tools table.
- `Pramnos_LLM_Tools_Guide.md`: `json_query` added to the `artifacts` skill's tool list.

## `read_storage_document`: the words of a file sent in a team conversation (FW-506)

The harness spec named a generic `read_storage_document` tool and it went unbuilt: letting the
model read an arbitrary stored file needs a permission model deciding whose files it may open,
and none existed. `Conversations\Files::pathFor()` already is one — the same rights as reading
the conversation the file was sent in, which `conversation_summary` already answers through for a
conversation's words rather than its files.

### Added

- `read_storage_document` (`Analyst::tools()`, alongside `conversation_summary`, wherever
  `Conversations::installed()`): the words of a file sent in a team conversation this person can
  read, through `DocumentText` — Word, OpenDocument, CSV/TSV, plain text, Markdown or a saved
  email. `file` is its id. A picture, video, PDF or archive — nothing `DocumentText` reads the
  words of — says so rather than nothing; a file from a conversation this person cannot read
  answers the same as one that does not exist.

### Documentation

- `Pramnos_LLM_Analyst_Guide.md`: `read_storage_document` added to the tools table, beside
  `conversation_summary`.

## `schema` can see more than one PostgreSQL schema, for an application split across several (FW-507)

`SchemaBuilder::tableNames()` only ever listed the connection's own schema, which is right for the
ordinary public-vs-private split but breaks for an application organised into several PostgreSQL
schemas by module on purpose — a table of any schema but the connection's own was invisible to
`schema`, and so to the model, even though `sql` could already query it by a qualified name once
it somehow knew the name. Found wiring up audit-log questions in an installation split into
`public`, `authserver`, `backend` and others, each a module of one application.

### Added

- `SchemaBuilder::tableNamesIn(array $schemas = [])`: every table across the PostgreSQL schemas
  named, a table of the connection's own kept bare, a table of any other `schema.table`-qualified,
  a system schema (`information_schema`, `pg_catalog`, `pg_toast`, `topology`, `_timescaledb_*`)
  left out whether or not it was named. A new method, not a new parameter on `tableNames()` —
  `SchemaBuilder` is not `final` and an overridden `tableNames()` elsewhere would fatal at class
  load on a new argument. Empty, or on MySQL (no second schema the way this is), the same as
  `tableNames()`.
- `'llm' => ['analyst' => ['schemas' => [...]]]`: `SchemaTool` reads it and calls `tableNamesIn()`
  in its place. Without it, nothing changes.

### Documentation

- `Pramnos_LLM_Analyst_Guide.md`: `schemas` added to the SQL/export config example and explained
  beside `schema`.
