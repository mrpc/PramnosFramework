## `pf-voice.js`: server dictation calls `onSilence` before `onEnd`, like the browser's own (FW-503)

With the browser's own speech recognition, a silence stops dictation and calls `onSilence`
synchronously; the recognition's own `onend` — which calls `onEnd` — arrives later, asynchronously.
A caller that follows the ordinary pattern, `onEnd: () => { if (listening) endConversation(); }`,
relies on that order: `onSilence` has already cleared `listening` by the time `onEnd` runs.

Dictation by a server (`createVoiceState({ listen: fn })`, FW-437 — Firefox, an installed app on
an iPhone) called them the other way round: `onEnd` fired as soon as the transcription promise
resolved, before `onSilence`. A caller using the same pattern read `listening` still `true` and
ended the conversation it had just restarted — invisible until server-based dictation started
working end to end, when the microphone that should have reopened never did.

### Fixed

- `serverDictation()`'s `finishServer()` now calls `opts.onSilence()` before `ended()` (which
  calls `opts.onEnd()`), matching the order the browser's own recognition path already used.

### Documentation

- `Pramnos_LLM_Analyst_Guide.md`, "Voice": the ordering made explicit, with why it matters for a
  caller's own `onEnd`.
