## `Memory::keep()`/`amend()`'s siblings `forget()`/`forgetShared()` log their own changelog event (FW-575)

### Added

`Pramnos\Llm\Chat\Memory` is not a `\Pramnos\Application\Model` — it writes `assist.chat_memory`
raw through the query builder — so it got nothing from the `$emitChanges` trait, and nothing a
memory went through (kept, corrected, forgotten) ever reached `pramnos.changelog_events`. A
reliability study of the assistant's memory had no way to answer "how many corrections has this
memory had" or "how often does learning forget what it just kept".

`keep()` now raises `ChangelogWriter::event('chat_memory', $id, …)` on the existing
`changelog_events` table — `model` or `learned` for a new memory depending on how it was told,
`corrected` for a correction — and `forget()`/`forgetShared()` raise `forgotten`. No new table: the
framework already has one for this (rule 14). `itemid` is the memory's own id; the details carry
only its kind and topic, never its content — the memory's own words are personal and stay out of
the log that outlives the memory itself.
