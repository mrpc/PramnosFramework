## The administration API answers to administrators, and the search box to everybody

Reported by a consuming project: with `OrganizationScope` set, `GET /admin/search` answered
403 to everybody. Looking at why showed something worse. `ApiAdmin` used the rule that
generated CRUD endpoints use: no grant is no opinion, and no opinion lets the call through.
So in an installation without organisations, any signed-in account could read
`/admin/users` (the user list, with addresses), `/admin/logs` and `/admin/summary`. With an
organisation in scope, nobody could, administrators included.

### Fixed

- **`users`, `logs` and `summary` are decided like the screens they serve.** `AdminAccess`
  checks `admin.users`, `admin.logs` and `admin.dashboard` at the administration floor, or
  by grant under `admin_access = permissions`. A permission-store grant for the action
  itself still opens it.
- **`search` needs only a signed-in user,** in an organisation too. **A search source with
  no `permission` shows only to administrators.** It used to show to everybody the endpoint
  let in, which once anyone may ask would have included the scaffolded `Users` source. The
  MCP `search` tool reads the same registry and gets the same rule.
- **The scaffolded `app/search.php`** says how to open a source to everybody.

### Documentation

- Search Guide: Permissions. API Guide: who may call the administration endpoints.
