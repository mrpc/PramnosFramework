## The administration API answers to administrators, and the search box to everybody

Reported by a consuming project: with `OrganizationScope` set, `GET /admin/search` answered
403 to everybody. Looking at why showed something worse. `ApiAdmin` used the rule that
generated CRUD endpoints use: no grant is no opinion, and no opinion lets the call through.
So in an installation without organisations, any signed-in account could read
`/admin/users` (the user list, with addresses), `/admin/logs` and `/admin/summary`. With an
organisation in scope, nobody could, administrators included.

### Fixed

- **`users`, `logs` and `summary` are decided like the screens they serve.** `AdminAccess`
  checks `admin.users`, `admin.logs` and `admin.dashboard` at the administration floor, or
  by grant under `admin_access = permissions`. A permission-store grant for the action
  itself still opens it.
- **`search` needs only a signed-in user,** in an organisation too. **A search source with
  no `permission` shows only to administrators.** It used to show to everybody the endpoint
  let in, which once anyone may ask would have included the scaffolded `Users` source. The
  MCP `search` tool reads the same registry and gets the same rule.
- **The scaffolded `app/search.php`** says how to open a source to everybody.

### Documentation

- Search Guide: Permissions. API Guide: who may call the administration endpoints.
- Upgrade Guide: two rows.

## A profile picture a user can set

`User` had `$photo` (a media usage) and `$avatarurl`, and `/me` returned `avatarurl`. But no
screen set either one, nothing turned `photo` into a URL, and `avatarurl` is not a column, so
it was always the `defaultAvatarUrl` setting. That setting is empty unless set. Asked for by
a consuming project.

### Added

- **A Profile Picture card on Account → Profile, in all three themes.** It uploads a JPEG,
  PNG or GIF, and **Remove** takes the picture away. `Account::profilephoto()` is a write
  action, so it needs a POST with the session's token.
- **`Pramnos\User\ProfilePhoto`.**
  - `set()` stores the upload through Media as a 256-pixel square crop, records the usage in
    `users.photo`, and releases the picture it replaces.
  - `remove()` takes the picture away, and `url()` gives its absolute URL.
  - `adoptFromProvider()` copies an SSO provider's picture for a user who has none, when
    `profile_photo_from_provider` is on. The copy goes through `OutboundUrl`.
  - `release()` gives a picture's usage back.
- **`User::load()` sets `avatarurl` from the picture,** so `/me`, the admin user list and
  every screen that reads it show the picture. `defaultAvatarUrl` applies only when there is
  no picture.
- **The OIDC `picture` claim carries the picture.** It used to read an `avatarurl` column
  that does not exist, so it was always null.
- **Erasing an account releases its picture, and the data export includes its URL.**
- **`Testing\Schema` recipes for `media` and `mediause`.**

### Fixed

- **Uploading an image that Media already has no longer leaves the new upload on disk.**
  The record points at the existing copy, and the second file was never deleted, so every
  repeated upload left one more orphan under `www/uploads`.

### Documentation

- Account Guide: "Profile picture". OAuth Client Guide: copying the provider's picture in
  the callback.
